## 二、认证 & 用户模块（/api/auth）

### 2.1 发送验证码

- ✅ 正常发送 `POST /api/auth/send-code`
  - 请求：`phone=13900001001`, `type=login`
  - 响应：HTTP 200，`expireIn=300`，`cooldown=60`。
- ✅ 手机号格式错误
  - 请求：`phone=13900001`
  - 响应：HTTP 400，`error="INVALID_PHONE_FORMAT"`。
- ✅ 发送频率限制
  - 同一手机号 60 秒内第二次请求。
  - 响应：HTTP 429，`error="TOO_MANY_REQUESTS"`，包含 `retryAfter` 字段。
- ⚠️ 白名单校验（与需求不一致）
  - 请求：`phone=18888888888`, `type=register`（未预先加入白名单）。
  - 实际响应：HTTP 200，验证码照常发送。
  - 需求文档期望：HTTP 403，`error="NOT_IN_WHITELIST"`。当前实现尚未在 `sendCode` 中接入白名单检查。

### 2.2 注册

- ✅ 正常注册学生
  - 请求：`POST /api/auth/register`，`phone=13900002001`, `code=123456`, `nickname=学生A`, `grade=初三`, `age=15`, `school=星河中学`。
  - 响应：HTTP 201，包含 `token`、`refreshToken`，`user.role="student"`，其它字段与请求一致。
- ✅ 缺少昵称
  - 请求未提供 `nickname`。
  - 响应：HTTP 400，`error="MISSING_REQUIRED_FIELD"`，`data.field="nickname"`。
- ✅ 重复注册
  - 同一手机号再次注册。
  - 响应：HTTP 409，`error="USER_EXISTS"`。

### 2.3 登录 / Token 生命周期

- ✅ 未注册手机号登录
  - 流程：
    1. `POST /api/auth/send-code` 向未注册手机号发送验证码（成功）。
    2. `POST /api/auth/login` 使用 `code=123456` 登录。
  - 响应：HTTP 404，`error="USER_NOT_FOUND"`。
- ✅ 已注册手机号登录
  - 使用 2.2 中注册成功的学生手机号：
    - `POST /api/auth/send-code` 正常发送。
    - `POST /api/auth/login` 返回 HTTP 200，带 `token`、`refreshToken` 以及正确的 user 信息。
- ⚠️ 验证码错误/过期
  - 尚未单独构造错误验证码或过期场景用例，待补充。

#### Token 相关接口

- ✅ `GET /api/auth/me`
  - 使用有效 accessToken 调用，返回 id/phone/nickname/role/年级/学校，与注册信息一致。
- ✅ `POST /api/auth/refresh-token`
  - 使用有效 refreshToken 调用，返回新的 accessToken 和 refreshToken，`expiresIn=604800`。
- ✅ `POST /api/auth/logout` + 再次刷新
  - 先使用 accessToken 调用 `/api/auth/logout` 返回 200。
  - 再使用旧 refreshToken 调用 `/api/auth/refresh-token`，返回 HTTP 401，`error="TOKEN_EXPIRED"`。
- ⚠️ 无 Token / 使用 accessToken 调用 refresh 接口
  - 尚未单独验证“缺少 Authorization”或“使用 accessToken 当 refreshToken”场景。

> 说明：`/api/users/me` 仅实现了 `/likes` 和 `/favorites` 子路由，当前后端不存在裸的 `GET /api/users/me` 用户信息接口，需求文档中的该接口需要后续对齐或补充实现。

- ✅ 核心链路畅通：健康检查、注册/登录/Token 刷新、白名单 CRUD、课时查询与批量调整在当前环境下均工作正常。

  - 第二次 `POST`：HTTP 200，`message="取消点赞"`，`data.isLiked=false`，likes 回落到 5。
- ✅ 问题收藏接口 `/api/questions/:id/favorite`
  - 首次 `POST`：HTTP 200，`message="收藏成功"`，favorites 由 3 → 4。
  - 第二次 `POST`：HTTP 200，`message="取消收藏"`，favorites 回落到 3。
- ✅ 用户侧列表
  - 在确保当前用户对该问题已点赞 + 收藏后：
    - `GET /api/users/me/likes` 返回包含该问题的列表，带有 `likedAt` 时间戳。
    - `GET /api/users/me/favorites` 返回包含该问题的列表，带有 `favoritedAt` 时间戳。
- ✅ 问题详情中的状态字段
  - `GET /api/questions/:id` 在未点赞/收藏时返回 `isLiked=false, isFavorited=false`。
  - 在完成点赞 + 收藏后再次查询，返回 `isLiked=true, isFavorited=true`，likes/favorites 计数与交互结果一致。

> 结论：点赞/收藏接口与用户侧列表、详情页状态字段联动正常，计数和布尔状态与预期一致。

## 七、审核 & AI 回调模块（第 7 部分）

使用 Prisma 预置一组 CLI 专用测试数据（问题与评论），并使用自签教师 Token（`sub=teacher_cli_audit_001`, `role=teacher`）。

### 7.1 审核列表与权限

- ✅ `GET /api/admin/audit/pending?type=question`
  - 返回 HTTP 200，`data.type="question"`，`list` 中包含：
    - `q-cli-ai-1`（AI 测试问题，pending）
    - `q-cli-audit-comment-1`（评论所属问题，pending）
    - `q-cli-audit-reject-1`、`q-cli-audit-approve-1` 等待审核问题。
  - `statistics.pending` ≥ 1，统计字段正确。  
- ✅ `GET /api/admin/audit/pending?type=comment`
  - 返回 HTTP 200，`data.type="comment"`，`list` 中包含预置的：
    - `c-cli-audit-pending-1`（待审核评论，`aiResult` 含“疑似违规”）。
    - `c-cli-audit-ban-1`（待封禁评论）等。
- ✅ 权限验证
  - 不带 Authorization 调用 pending：HTTP 401，`error="UNAUTHORIZED"`。
  - 使用学生 Token 调用 pending：HTTP 403，`error="PERMISSION_DENIED"`。

### 7.2 问题审核通过/驳回

- ✅ 审核通过问题 `/api/admin/audit/:id/approve`
  - 对 `q-cli-audit-approve-1` 调用 `POST /approve`，body：`{type:"question", isGoodQuestion:true, score:5, tags:["tag-a"], difficulty:"medium"}`。
  - 响应：HTTP 200，`message="审核完成：已通过"`，`data.status="approved"`，`isGoodQuestion=true`，`score=5`，`tags` 与 `difficulty` 更新成功。
- ✅ 审核驳回问题 `/api/admin/audit/:id/reject`
  - 先以空 reason 调用：返回 HTTP 400，`error="REASON_REQUIRED"`，校验正常。
  - 再以非空 reason 调用：对 `q-cli-audit-reject-1`，返回 HTTP 200，`data.status="rejected"`，`data.rejectReason` 包含驳回原因，`rejectedBy` 为教师 ID。

> 说明：数据库层面对状态和审核日志的细节未逐条检查，但从接口返回和统计数据看，问题审核的主流程是闭环的。

### 7.3 评论审核通过/封禁

- ✅ 审核通过评论 `/api/admin/audit/:id/approve`
  - 对 `c-cli-audit-pending-1` 调用，body：`{type:"comment"}`。
  - 响应：HTTP 200，`message="审核完成：已通过"`，`data.status="approved"`。
- ✅ 封禁评论 `/api/admin/audit/:id/ban`
  - 对 `c-cli-audit-ban-1` 调用，body：`{type:"comment", reason:"包含侮辱性词汇"}`。
  - 响应：HTTP 200，`message="审核完成：已封禁"`，`data.status="banned"`，`banReason` 包含封禁原因。

### 7.4 置顶/取消置顶与 AI 回调

- ✅ 置顶/取消置顶 `/api/admin/audit/questions/:id/pin`
  - 针对 `q-cli-audit-pin-1` 连续调用两次：
    - 第一次：HTTP 200，`data.isPinned=true`，消息“已置顶”。
    - 第二次：HTTP 200，`data.isPinned=false`，消息“已取消置顶”。
- ✅ AI 审核回调 `/api/internal/ai-check`
  - 对 `q-cli-ai-1` 调用：body：`{targetType:"question", targetId:"q-cli-ai-1", result:{safe:true, score:4.5}}`。
  - 响应：HTTP 200，`data.status="approved"`，`data.aiResult` 为包含 `safe`、`score` 的 JSON 字符串。

> 差异点：当前 AI 回调接口未做任何鉴权，任何客户端都可直接调用；需求文档中提到“未授权外部调用应拒绝”，这部分需要后续在实现中补充安全校验（例如签名/Token 或 IP 白名单）。
