## 一、系统概述

### 1.1 应用架构
- **前端**: React + TypeScript
- **后端需求**: RESTful API 或 GraphQL
- **数据库**: 关系型数据库 (MySQL/PostgreSQL) 或 NoSQL (MongoDB)
- **存储**: OSS 对象存储（图片、音频文件）
- **AI服务**: 内容审核API接入

### 1.2 用户角色权限

| 角色 | 权限说明 |
|-----|---------|
| **学生（有效期内）** | 可提问、点赞、收藏、评论（自己的问题） |
| **学生（已过期）** | 仅可浏览、点赞、收藏（权限降级为家长模式） |
| **家长** | 可浏览、点赞、收藏（只读权限） |
| **教师/管理员** | 可提问、回答、录音、点赞、收藏、评论、审核、置顶、打分、管理用户白名单、管理课时 |

> **重要说明**: 
> - 教师即管理员，拥有系统最高权限，包括内容审核和用户管理权限。
> - 学生和家长的课时有效期是共享的，由管理员统一设置。
> - 学生课时过期后，权限自动降级为家长模式（只能点赞和收藏）。
> - 家长权限不受课时过期影响，始终保持只读权限。

### 1.3 注册控制机制

本系统采用 **白名单注册制度**：
- ✅ 只有管理员添加到白名单的手机号才能注册
- ✅ 白名单记录包括：手机号、姓名、预设角色
- ✅ 未在白名单的手机号将无法完成注册
- ✅ 管理员可以随时管理白名单（添加/删除）

```sql

phone           VARCHAR(11) UNIQUE NOT NULL
nickname        VARCHAR(50) NOT NULL
avatar          VARCHAR(500)
role            ENUM('student', 'parent', 'teacher') NOT NULL
school          VARCHAR(100)
created_at      TIMESTAMP DEFAULT NOW()
updated_at      TIMESTAMP DEFAULT NOW()
is_active       BOOLEAN DEFAULT TRUE
is_banned       BOOLEAN DEFAULT FALSE
```

#### **用户白名单表 (user_whitelist)** ⭐新增
```sql
id              VARCHAR(36) PRIMARY KEY
phone           VARCHAR(11) UNIQUE NOT NULL
name            VARCHAR(50) NOT NULL        -- 真实姓名
role            ENUM('student', 'parent', 'teacher') NOT NULL
is_registered   BOOLEAN DEFAULT FALSE       -- 是否已注册
user_id         VARCHAR(36) NULL (FK users.id)  -- 关联的用户ID
created_by      VARCHAR(36) NOT NULL (FK users.id)  -- 添加人
created_at      TIMESTAMP DEFAULT NOW()
registered_at   TIMESTAMP                   -- 注册时间
notes           TEXT                        -- 备注信息
valid_until     TIMESTAMP                   -- 课时有效期

INDEX idx_phone (phone)
INDEX idx_role (role)
INDEX idx_is_registered (is_registered)
```

**说明：**
- `phone`: 允许注册的手机号
- `name`: 用户真实姓名（用于管理识别）
- `role`: 预设角色，注册时自动分配
- `is_registered`: 标记是否已完成注册
- `user_id`: 注册后关联到实际用户记录
- `created_by`: 记录是哪位管理员添加的
- `valid_until`: 课时有效期，过期后权限降级

## 三、API接口设计

### 3.1 认证相关 (Auth)

#### **1. 发送验证码**
```
POST /api/auth/send-code
请求体: { phone: string }
响应: { success: boolean, message: string }
```

#### **2. 验证手机号是否在白名单** ⭐新增
```
POST /api/auth/check-whitelist
请求体: { phone: string }
响应: { 
  inWhitelist: boolean, 
  role?: string,
  name?: string,
  message: string 
}
```

**说明：** 
- 注册前先验证手机号是否在白名单中
- 如果在白名单，返回预设的角色和姓名
- 如果不在白名单，返回 `inWhitelist: false`

#### **3. 登录**
```
POST /api/auth/login
请求体: { phone: string, code: string }
响应: { 
  token: string, 
  user: { 
    id, nickname, avatar, role, phone, school 
  } 
}
```

#### **4. 注册** ⚠️已修改
```
POST /api/auth/register
请求体: { 
  phone: string, 
  code: string, 
  nickname?: string,
  school?: string 
}
响应: { 
  token: string, 
  user: { id, nickname, avatar, role, phone, school } 
}
```

**重要变更：**
- ❌ 移除 `inviteCode` 字段
- ✅ 后端根据白名单中的 `role` 自动分配用户角色
- ✅ 注册成功后，更新白名单记录的 `is_registered` 和 `user_id`

**注册流程：**
```
1. 验证手机号和验证码
   ↓
2. 查询白名单表（user_whitelist）
   - 不在白名单 → 返回 403 Forbidden
   ↓
3. 创建用户记录
   - 使用白名单中预设的 role
   - 默认昵称使用白名单中的 name
   ↓
4. 更新白名单记录
   - is_registered = true
   - user_id = 新用户ID
   - registered_at = 当前时间
   ↓
5. 返回 JWT Token 和用户信息
```

#### **5. 退出登录**
```
POST /api/auth/logout
请求头: Authorization: Bearer {token}
响应: { success: boolean }
```

### 3.3 用户白名单管理 (Whitelist) ⭐新增模块

#### **38. 获取白名单列表**
```
GET /api/admin/whitelist?page=1&limit=20&search=&role=all&status=all
请求头: Authorization: Bearer {token}
查询参数:
  - page: 页码
  - limit: 每页数量
  - search: 搜索关键词（手机号或姓名）
  - role: 角色筛选（all | student | teacher | parent）
  - status: 状态筛选（all | registered | pending）
响应: {
  users: [
    {
      id, phone, name, role, isRegistered, 
      userId, createdAt, registeredAt, notes
    }
  ],
  stats: {
    total, registered, pending,
    students, teachers, parents
  },
  total, page, totalPages
}
权限: 教师/管理员
```

#### **39. 添加用户到白名单**
```
POST /api/admin/whitelist
请求头: Authorization: Bearer {token}
请求体: {
  phone: string,
  name: string,
  role: 'student' | 'teacher' | 'parent',
  notes?: string
}
响应: { 
  success: boolean, 
  user: { id, phone, name, role, ... } 
}
权限: 教师/管理员
```

**验证规则：**
- 手机号必须是11位数字
- 手机号不能重复
- 姓名不能为空
- 角色必须是有效值

#### **40. 从白名单移除用户**
```
DELETE /api/admin/whitelist/:id
请求头: Authorization: Bearer {token}
响应: { success: boolean, message: string }
权限: 教师/管理员
```

**业务规则：**
- 如果用户已注册（`is_registered = true`），移除时需要额外确认
- 移除后该手机号将无法登录系统
- 建议软删除而非物理删除，以保留历史记录

#### **41. 批量导入白名单** ⚠️可选功能
```
POST /api/admin/whitelist/batch-import
请求头: Authorization: Bearer {token}
请求体: FormData { file: File }  // Excel/CSV文件
响应: { 
  success: boolean,
  imported: number,
  failed: number,
  errors: [ { row, phone, reason } ]
}
权限: 教师/管理员
```

**文件格式：**
```csv
手机号,姓名,角色,备注
13800138000,张三,student,初三1班
13900139000,李四,parent,张三家长
```

#### **42. 导出白名单** ⚠️可选功能
```
GET /api/admin/whitelist/export?format=csv
请求头: Authorization: Bearer {token}
响应: 文件下载
权限: 教师/管理员
```

#### **43. 获取白名单统计信息**
```
GET /api/admin/whitelist/stats
请求头: Authorization: Bearer {token}
响应: {
  total: number,
  registered: number,
  pending: number,
  byRole: {

    teacher: number,

  },
```

## 五、核心业务逻辑

### 5.1 白名单注册流程 ⭐新增

#### **完整注册流程：**

```
【用户端】
1. 用户输入手机号
   ↓
2. 点击"获取验证码"
   ↓
3. 前端调用 /api/auth/check-whitelist
   - 验证手机号是否在白名单
   ↓
4. 如果不在白名单
   → 提示：该手机号暂未开通注册权限，请联系管理员
   → 阻止发送验证码
   ↓
5. 如果在白名单
   → 发送验证码
   → 显示预设角色（可选）
   ↓
6. 用户输入验证码，点击注册
   ↓
7. 后端验证白名单
   - 创建用户记录
   - 分配白名单中的角色
   - 更新白名单状态
   ↓
8. 注册成功，返回Token

【管理端】
1. 管理员登录系统
   ↓
2. 进入"用户白名单管理"
   ↓
3. 添加新用户
   - 输入手机号、姓名、角色
   - 可选添加备注
   ↓
4. 提交后，用户可使用该手机号注册
   ↓
5. 查看白名单列表
   - 查看哪些已注册
   - 查看哪些待注册
```

#### **关键验证点：**

1. **注册时验证：**
```javascript
// 后端伪代码
async function register(phone, code) {
  // 1. 验证验证码
  if (!verifyCode(phone, code)) {
    return error(1002, '验证码错误');
  }
  
  // 2. 查询白名单
  const whitelistUser = await db.userWhitelist.findOne({ phone });
  if (!whitelistUser) {
    return error(4001, '该手机号未开通注册权限');
  }
  
  // 3. 检查是否已注册
  if (whitelistUser.isRegistered) {
    return error(4002, '该手机号已注册，请直接登录');
  }
  
  // 4. 创建用户
  const user = await db.users.create({
    phone: phone,
    nickname: whitelistUser.name, // 使用白名单中的姓名
    role: whitelistUser.role,     // 使用白名单中的角色
    ...
  });
  
  // 5. 更新白名单
  await db.userWhitelist.update(whitelistUser.id, {
    isRegistered: true,
    userId: user.id,
    registeredAt: new Date()
  });
  
  // 6. 返回Token
  return { token: generateJWT(user), user };
}
```

2. **登录时验证：**
```javascript
// 检查用户是否被移出白名单
async function login(phone, code) {
  const user = await db.users.findOne({ phone });
  const whitelistUser = await db.userWhitelist.findOne({ phone });
  
  // 如果白名单记录被删除，禁止登录
  if (!whitelistUser) {
    return error(4003, '账号已被停用，请联系管理员');
  }
  
  // 正常登录流程
  ...
}
```

### 5.2 审核流程

#### **AI初筛 + 人工审核双重机制**

```
1. 用户提交内容（问题/回答/评论）
   ↓
2. 后端调用AI内容审核API
   - 检测敏感词、违规内容
   - 生成审核结果（aiResult字段）
   ↓
3. 内容状态设为 'pending'（待审核）
   ↓
4. 教师在审核管理页查看
   ↓
5. 教师决策：
   - 审核通过 → status = 'approved'
   - 审核驳回 → status = 'rejected' + 填写原因
   - 封禁内容 → status = 'banned'
   ↓
6. 前端仅显示 status = 'approved' 的内容
```

#### **审核权限**
- 仅教师/管理员可执行审核操作
- 审核日志记录到 `audit_logs` 表

## 十二、后端技术栈推荐

### 方案1：Node.js + Express
- **优势**: 与前端同语言，开发效率高
- **推荐框架**: Express.js / Nest.js
- **ORM**: Prisma / TypeORM
- **数据库**: PostgreSQL / MySQL

### 方案2：Python + Django/Flask
- **优势**: AI集成方便，生态丰富
- **推荐框架**: Django REST Framework / FastAPI
- **ORM**: Django ORM / SQLAlchemy
- **数据库**: PostgreSQL

### 方案3：Java + Spring Boot
- **优势**: 企业级稳定性，性能优秀
- **推荐框架**: Spring Boot + MyBatis
- **数据库**: MySQL
- **缓存**: Redis
