# 生产环境部署 Checklist（1 核 1 GB 场景优先版）

> 建议在每次上线或迁移环境前完整走一遍本清单，并记录执行人和时间。

---

## 一、基础环境与资源

- [ ] **机器规格确认**
  - [ ] CPU 为 1 核（或以上），内存 ≥ 1 GB。
  - [ ] 磁盘空间充足（预留至少 10GB 以上给 DB 与日志）。
- [ ] **系统基础工具**
  - [ ] 已安装 Docker 与 docker compose（版本在官方支持范围内）。
  - [ ] 已配置时区与 NTP，同步服务器时间。
- [ ] **端口与防火墙**
  - [ ] 确认对外暴露端口：HTTP（如 80/3000）、Postgres（通常仅内网）、Redis（通常仅内网）。
  - [ ] 防火墙/安全组规则已限制数据库和 Redis 仅对后端机器开放。

---

## 二、配置与密钥

- [ ] **环境变量/配置文件**
  - [ ] `.env` 或 docker-compose 环境变量中，数据库地址/账号/库名均为生产值。
  - [ ] `DATABASE_URL` 包含 `connection_limit=5` 等限制参数，避免连接数过高。
- [ ] **JWT 与安全相关配置**
  - [ ] `JWT_SECRET` 为高强度随机字符串，且不与测试/开发环境共用。
  - [ ] `JWT_EXPIRES_IN` 设置符合业务（如 `7d`），并已与前端对齐。
- [ ] **第三方服务（如 OSS、短信、AI）**
  - [ ] 如已接入真实短信/OSS/AI 服务，环境变量中密钥均为生产密钥。
  - [ ] 确认未将测试 Key/测试 Endpoint 用于生产环境。

---

## 三、数据库与缓存

- [ ] **PostgreSQL**
  - [ ] 已按照 `deploy/2-one-core-1g-deploy-notes.md` 或 `deploy/4-docker-compose.1c1g.yml` 设置内存与连接数参数（如 `max_connections=20`、`shared_buffers=128MB`）。
  - [ ] 已执行所有 Prisma 迁移：`npm run prisma:migrate`（在 backend 目录）。
  - [ ] 确认生产库中无明显脏数据或测试数据（或已清理）。
- [ ] **Redis（如启用）**
  - [ ] 已设置 `maxmemory`（例如 64–128MB）与 `maxmemory-policy allkeys-lru`。
  - [ ] 未用于存储大体积 payload，只存一些计数/缓存等轻量数据。

---

## 四、应用构建与运行

- [ ] **依赖与构建**
  - [ ] 在 `backend/` 目录执行 `npm ci` 且无错误。
  - [ ] 执行 `npm run build` 成功，生成 `dist/` 目录。
- [ ] **测试与质量**
  - [ ] 在 `backend/` 目录执行 `npm test -- --runInBand --testPathPattern=integration` 全部通过。
  - [ ] 集成测试数量与《后端-测试用例.md》主要用例保持一致（当前 15 套、65 个用例已通过）。
- [ ] **启动方式**
  - [ ] 直接运行：`node dist/server.js` 本地可正常启动。
  - [ ] 如使用 docker：在 `deploy/` 目录中运行 `docker compose -f docker-compose.1c1g.yml up -d` 启动无报错。
  - [ ] 若使用 PM2：已通过 `pm2 start dist/server.js --name kpqa-backend --node-args="--max-old-space-size=512"` 启动，并 `pm2 save`。

---

## 五、健康检查与功能验证

- [ ] **健康检查**
  - [ ] `GET /health` 返回 `status: "ok"`，并已在负载均衡或健康检查工具中配置此端点。
- [ ] **核心功能 Smoke Test（可用 Postman 或 curl）**
  - [ ] 认证流程：发送验证码、注册、登录、刷新 token、退出登录。
  - [ ] 白名单操作：教师账号可增删改查白名单，学生/家长越权被正确拒绝。
  - [ ] 课时查询与批量更新：过期逻辑正确、批量调整生效。
  - [ ] 问题提问与列表/详情：学生/教师可提问，家长被禁止；已审核问题可在列表/详情正确展示。
  - [ ] 回答与评论：教师可回答，学生/家长权限符合预期；评论权限规则（仅作者/教师）正确。
  - [ ] 点赞与收藏：问题点赞/收藏、我的点赞/收藏列表接口正常。
  - [ ] 审核操作：待审核问题/评论列表、审核通过/驳回/封禁、置顶/取消置顶行为与状态变更正确。
  - [ ] 行为埋点：`POST /api/behavior/log` 可写入行为日志。
  - [ ] 上传签名：`GET /api/upload/signature` 返回图片/音频上传签名，音频签名仅教师可获取。
  - [ ] 通知：通知列表/未读数量/标记已读逻辑符合预期。

---

## 六、监控与告警

- [ ] **系统监控**
  - [ ] 使用 `htop`/`top` 或监控系统确认 CPU/内存峰值在合理范围（整体内存使用常态 < 80%）。
  - [ ] 使用 `docker stats` 查看 `postgres` / `redis` / `backend` 容器的 CPU 与内存占用情况。
- [ ] **应用监控**
  - [ ] 若使用 PM2，已通过 `pm2 monit` 观察一段时间，确认无频繁重启或异常。
  - [ ] 错误日志（pino 输出）中无持续性报错（如数据库连接错误、未捕获异常等）。
- [ ] **告警配置（可选）**
  - [ ] 为 CPU 高负载、内存接近满、容器重启次数异常等设置告警（如使用监控平台或简单脚本）。

---

## 七、备份与回滚方案

- [ ] **数据库备份**
  - [ ] 已配置定期备份 Postgres（如每日 `pg_dump`）并验证过恢复流程。
- [ ] **应用回滚**
  - [ ] 保留上一版构建产物（或镜像标签），可通过切换镜像/版本快速回退。
  - [ ] 明确回滚步骤：停止当前版本 → 切换镜像/代码 → 启动旧版本 → 验证健康。

---

## 八、上线确认

- [ ] 所有上述勾选项已由责任人检查并确认。
- [ ] 已在 HelloAGENTS 或项目文档中记录本次上线的版本号、时间和变更摘要。
