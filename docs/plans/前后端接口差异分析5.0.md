## 发现的问题

### 🔴 38. User.classHours 字段完全不匹配

**问题：** 前端 `User.classHours` 类型与后端返回的数据结构完全不同

**前端类型：**
```typescript
// src/types/index.ts
export interface User {
    // ...
    classHours?: {
        total: number;      // ❌ 后端不返回
        used: number;        // ❌ 后端不返回
        remaining: number;   // ❌ 后端不返回
    };
}
```

**后端返回：**
```typescript
// backend/src/services/class-hours.service.ts
return {
    userId: user.id,          // ✅ 返回
    phone: user.phone,        // ✅ 返回
    name: whitelist?.name ?? user.nickname,  // ✅ 返回
    role: user.role,          // ✅ 返回
    validUntil,               // ✅ 返回
    isExpired,                // ✅ 返回
    remainingDays,            // ✅ 返回
    status                    // ✅ 返回
    // ❌ 缺少 total, used, remaining
};
```

**影响：**
- 前端代码尝试访问 `user.classHours.total` 会得到 `undefined`
- 前端代码尝试访问 `user.classHours.remaining` 会得到 `undefined`
- 课时状态展示功能失效
- 前端类型定义与实际数据完全脱节

### ⚠️ 39. 课时数据语义不明确

**问题：** 后端返回 `remainingDays`（剩余天数），前端期望 `remaining`（剩余课时数）

**后端逻辑：**
```typescript
// backend/src/services/class-hours.service.ts
if (validUntil) {
    const diff = validUntil.getTime() - now.getTime();
    remainingDays = Math.round(diff / MS_PER_DAY);  // 计算剩余天数
    isExpired = diff < 0;
}

return {
    // ...
    remainingDays,  // 天数
    status: isExpired ? 'expired' : 'active'
};
```

**前端期望：**
```typescript
// src/types/index.ts
classHours?: {
    total: number;      // 总课时数
    used: number;       // 已使用课时数
    remaining: number;  // 剩余课时数
};
```

**影响：**
- 后端基于"有效期"计算剩余天数，前端期望基于"课时数"计算剩余课时
- 业务逻辑理解不一致
- 需要确认产品需求：是按有效期还是按课时数计算

### ⚠️ 45. 图片上传强依赖第三方图床

**问题：** 图片上传流程涉及多步骤，前端需要解析多种图床响应格式

**当前流程：**
```
前端 → 后端 /upload/signature → 获取签名
前端 → 第三方图床直传 → 解析响应
前端 → 提取 imageUrl → 返回
```

**潜在问题：**
| 问题 | 描述 | 影响 |
|------|------|------|
| 第三方依赖 | 依赖 ImgURL 等图床服务 | 图床故障导致上传失败 |
| 响应格式不统一 | 需要兼容多种响应结构 | 代码复杂度高 |
| Token 泄露风险 | URL 中包含 `?token=sk-xxx` | 安全隐患 |
| 无后备方案 | 图床无响应时直接报错 | 用户体验差 |

**建议改进：** 后端代理上传 + 流式转发 = ✅ 既安全，又不占硬盘

**改进方案：**
```
前端 → 后端 /upload/image (文件流) → 后端内部转发 → 图床
                                                    │
                                                    ▼
                                               返回 imageUrl
```

**流式转发核心优势：**
1. ✅ **Token 不暴露**：后端内部处理，前端不接触
2. ✅ **不占硬盘**：文件不落地，内存中直接转发
3. ✅ **前端简化**：只需调用一个接口
4. ✅ **错误统一**：后端集中处理异常

### 优先级 2（中）- 考虑优化

#### 45. 统一图片上传接口

**方案 A：后端代理上传（推荐）**

```typescript
// 新增接口
POST /upload/image
Content-Type: multipart/form-data

Request: { file: File }
Response: { imageUrl: string }

// 前端简化
uploadImage: async (file: File, context?: UploadImageContext): Promise<UploadImageResult> => {
    const formData = new FormData();
    formData.append('file', file);

    const { data } = await api.post<ApiResponse<UploadImageResult>>(
        '/upload/image',
        formData
    );
    return data.data;
}
```

**优点：**
- 前端代码简化
- 后端统一处理图床切换
- Token 不暴露给前端
- 错误处理更集中
