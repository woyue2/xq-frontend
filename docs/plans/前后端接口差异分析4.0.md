## 发现的问题

### ⚠️ 24. LikePayload.targetType 类型过于宽松

**问题：** 前端 `LikePayload.targetType` 允许 `'answer'`，但后端路由层限制了只支持 `'question'`

**前端类型：**
```typescript
// src/types/api.ts
export interface LikePayload {
    targetType: 'question' | 'answer';  // ⚠️ 允许 answer
    targetId: string;
    action: 'like' | 'unlike';
}
```

**后端路由：**
```typescript
// backend/src/routes/interaction.routes.ts
if (targetType !== 'question') {
    throw new AppError(
        400,
        'UNSUPPORTED_TARGET_TYPE',
        '当前仅支持问题点赞'  // ⚠️ 只支持 question
    );
}
```

**影响：**
- 前端类型定义误导开发者，误以为支持 answer 点赞
- 运行时才会抛出错误，编译时无法发现类型不匹配
- API 文档与实际实现不一致

---

### ❌ 25. MyLikedQuestion 缺少 authorAvatar 字段

**问题：** 前端 `MyLikedQuestion` 类型定义了 `authorAvatar` 字段，但后端 `listUserLikes` 不返回该字段

**前端类型：**
```typescript

    id: string;
    title: string;
    content?: string | null;
    authorName: string;
    authorAvatar?: string;  // ❌ 后端不返回
    likes: number;
    favorites: number;
    answers: number;
    createdAt: string;
    likedAt: string;
}
```

**后端返回：**
```typescript
// backend/src/services/interaction.service.ts
return {
    list: likes
        .map((l) => {
            const q = map.get(l.targetId);
            return {
                id: q.id,
                title: q.title,
                content: q.content,
                authorName: q.authorName,
                // ❌ 缺少 authorAvatar
                likes: q.likes,
                favorites: q.favorites,

                likedAt: l.createdAt
```

**影响：**

## 发现的问题

### ⚠️ 28. Notification.userId 前端冗余

**问题：** 前端 `Notification` 类型定义了 `userId` 字段，但后端不返回该字段

**前端类型：**
```typescript
// src/types/api.ts
export interface Notification {
    id: string;
    userId: string;  // ❌ 后端不返回
    type: 'answer' | 'comment' | 'audit_result' | 'system' | 'new_answer';
    title: string;
    content?: string;
    targetType?: string;
    targetId?: string;
    isRead: boolean;
    createdAt: string;
}
```

**后端返回：**
```typescript
// backend/src/routes/notification.routes.ts
notifications: notifications.map((n) => ({
    id: n.id,
    type: n.type,
    title: n.title,
    content: n.content,
    targetType: n.targetType,
    targetId: n.targetId,
    isRead: n.isRead,
    createdAt: n.createdAt
    // ❌ 缺少 userId
}))
```

**影响：**
- 前端调用 `getNotifications` 返回的数据不包含 `userId`
- 前端代码尝试访问 `notification.userId` 会得到 `undefined`
- 该字段冗余，因为通知本身就是当前用户的通知

---

### ⚠️ 29. Notification.type 类型过窄

**问题：** 前端 `Notification.type` 限制为 `'answer' | 'comment' | 'audit_result' | 'system' | 'new_answer'`，但后端返回的是 `string` 类型

**前端类型：**
```typescript
// src/types/api.ts
type: 'answer' | 'comment' | 'audit_result' | 'system' | 'new_answer';  // ⚠️ 固定类型
```

**后端返回：**
```typescript
// backend/src/routes/notification.routes.ts
type: n.type;  // ⚠️ 原始字符串，未验证
```

**影响：**
- 如果后端数据库中存在其他类型的通知，前端无法正确解析
- 类型定义与实际运行时类型不一致
- 未来新增通知类型需要同步更新前端类型

---

### ⚠️ 30. unread 参数类型不匹配

**问题：** 前端传递 `unread` 为 `boolean` 类型，但后端从 query string 读取并转换为 `boolean`

**前端调用：**
```typescript
// src/services/api.ts
getNotifications: async (params: { page?: number; limit?: number; unread?: boolean }) => {
    // ...
    await api.get<...>('/notifications', { params });  // unread: boolean
}
```

**后端读取：**
```typescript
// backend/src/routes/notification.routes.ts
const unreadOnly = String(req.query.unread ?? '').toLowerCase() === 'true';
// ⚠️ 将 string 'true'/'false' 转换为 boolean
```

**影响：**
- 前端传递 `unread: false` 时，后端会将其转换为 `boolean false`，逻辑正确
- 前端传递 `unread: undefined` 时，后端 query 不包含该参数，默认 `false`，逻辑正确
- 类型声明不一致可能导致 TypeScript 警告
