# 前后端接口差异分析 9.0

> 本文档记录 user-me（用户信息管理）模块的前后端接口字段一致性分析结果。

## 模块健康度评估

| 维度 | 评分 | 说明 |
|------|------|------|
| 接口完整性 | ⚠️ 中等 | 缺少获取用户信息专用方法，需复用 updateProfile 调用方式 |
| 类型安全性 | ⚠️ 中等 | PATCH /users/me 响应缺少 expiresAt 和 classHours |
| 参数字段一致性 | ✅ 良好 | 参数命名和类型基本一致 |
| 总体健康度 | ⚠️ 中等 | 响应结构可优化 |

## 发现的问题

### 问题 91：PATCH /users/me 响应缺少 expiresAt 和 classHours 字段

**优先级**: 高

**问题描述**:
后端 `GET /users/me` 接口返回用户信息时包含 `expiresAt` 和 `classHours` 字段，但 `PATCH /users/me` 接口更新用户信息后返回的响应中缺少这两个字段。这导致前端在更新用户信息后无法立即获取最新的课时状态。

**后端现状**:
```typescript
// backend/src/routes/user-me.routes.ts
// GET /users/me 返回
return res.json({
  data: {
    id: user.id,
    phone: user.phone,
    name: user.name ?? undefined,
    nickname: user.nickname,
    avatar: user.avatar ?? undefined,
    role: user.role,
    grade: user.grade ?? undefined,
    age: user.age ?? undefined,
    school: user.school ?? undefined,
    expiresAt: user.expiresAt ?? undefined,
    classHours  // ✅ 返回课时状态
  }
});

// PATCH /users/me 返回
return res.json({
  data: {
    id: updatedUser.id,
    phone: updatedUser.phone,
    name: updatedUser.name ?? undefined,
    nickname: updatedUser.nickname,
    avatar: updatedUser.avatar,
    role: updatedUser.role,
    grade: updatedUser.grade,
    age: updatedUser.age,
    school: updatedUser.school
    // ❌ 缺少 expiresAt 和 classHours
  }
});
```

**前端现状**:
```typescript
// src/services/api.ts
export const userService = {
    updateProfile: async (data: UpdateProfilePayload) => {
        const { data: res } = await api.patch<ApiResponse<User>>('/users/me', data);
        return res.data;
    }
};
```

**修复建议**:
```typescript
// 后端 PATCH /users/me 响应补充 expiresAt 和 classHours
userMeRouter.patch(
  '/',
  async (req: AuthenticatedRequest, res: Response, next: NextFunction) => {
    // ... 更新逻辑

    const updatedUser = await userService.updateProfile(req.user.id, data);

    // 获取更新后的课时状态
    let classHours: Awaited<ReturnType<typeof classHoursService.getUserClassHours>> | null = null;
    try {
      classHours = await classHoursService.getUserClassHours(updatedUser.id);
    } catch {
      classHours = null;
    }

    return res.json({
      code: 200,
      message: 'success',
      data: {
        id: updatedUser.id,
        phone: updatedUser.phone,
        name: updatedUser.name ?? undefined,
        nickname: updatedUser.nickname,
        avatar: updatedUser.avatar ?? undefined,
        role: updatedUser.role,
        grade: updatedUser.grade ?? undefined,
        age: updatedUser.age ?? undefined,
        school: updatedUser.school ?? undefined,
        expiresAt: updatedUser.expiresAt ?? undefined,
        classHours  // ✅ 添加
      },
      timestamp: Date.now()
    });
  }
);
```

### 问题 92：前端缺少 getUserInfo 专用方法

**优先级**: 中

**问题描述**:
前端 `profileService` 只提供了 `getMyLikes` 和 `getMyFavorites` 方法，没有专门获取用户基本信息的 `getUserInfo` 方法。前端在需要获取当前用户信息时，需要通过 `updateProfile` 的调用方式或自行调用 API。

**前端现状**:
```typescript
// src/services/api.ts
export const profileService = {
    // 缺少 getUserInfo 方法
    getMyLikes: async (params?: { page?: number; pageSize?: number }) => { /* ... */ },
    getMyFavorites: async (params?: { page?: number; pageSize?: number }) => { /* ... */ }
};

// src/services/api.ts
export const userService = {
    updateProfile: async (data: UpdateProfilePayload) => {
        const { data: res } = await api.patch<ApiResponse<User>>('/users/me', data);
        return res.data;
    }
};
```

**修复建议**:
```typescript
// 前端添加 getUserInfo 方法
export const userService = {
    getUserInfo: async () => {
        const { data: res } = await api.get<ApiResponse<User>>('/users/me');
        return res.data;
    },
    updateProfile: async (data: UpdateProfilePayload) => {
        const { data: res } = await api.patch<ApiResponse<User>>('/users/me', data);
        return res.data;
    }
};
```

### 问题 93：PATCH /users/me 后端年龄验证返回错误格式不一致

**优先级**: 中

**问题描述**:
后端 `PATCH /users/me` 接口对 `age` 字段的验证失败时，返回的错误格式与其他字段不一致。age 验证失败返回结构化错误，其他字段验证失败可能返回简单错误。

**后端现状**:
```typescript
// backend/src/routes/user-me.routes.ts
if (key === 'age') {
  if (value === null || value === undefined || value === '') {
    return acc;
  }
  const num = typeof value === 'number' ? value : Number(value);
  if (!Number.isInteger(num) || num < 0 || num > 120) {
    throw new AppError(
      400,
      'INVALID_PARAMS',
      '年龄格式不正确',
      {
        errors: [
          { field: 'age', message: 'age 必须为 0~120 的整数' }
        ]
      }
    );
  }
  acc.age = num;
  return acc;
}

// 其他字段验证
if (
  (key === 'name' ||
    key === 'nickname' ||
    key === 'avatar' ||
    key === 'grade' ||
    key === 'school') &&
  value !== null &&
  value !== undefined
) {
  if (typeof value !== 'string') {
    throw new AppError(
      400,
      'INVALID_PARAMS',
      '参数类型错误',
      {
        errors: [
          { field: key, message: `${key} 必须为字符串` }
        ]
      }
    );
  }
  acc[key] = value;
}
```

**问题分析**:
age 字段的验证消息是"年龄格式不正确"，而其他字段是"参数类型错误"。虽然 age 的消息更语义化，但与其他字段的格式不统一。

**修复建议**:
```typescript
// 统一错误消息格式
if (!Number.isInteger(num) || num < 0 || num > 120) {
  throw new AppError(
    400,
    'INVALID_PARAMS',
    'age 必须在 0~120 之间',
    {
      errors: [
        { field: 'age', message: 'age 必须在 0~120 之间' }
      ]
    }
  );
}
```

### 问题 94：后端 PATCH /users/me 缺少 nickname 长度限制

**优先级**: 低

**问题描述**:
后端 `PATCH /users/me` 接口对 `nickname` 字段没有长度限制验证，虽然前端类型定义中没有明确限制，但业务上通常需要限制昵称长度（如 2-20 字符）。

**后端现状**:
```typescript
// backend/src/routes/user-me.routes.ts
const allowedFields = ['name', 'nickname', 'avatar', 'grade', 'age', 'school'];
// nickname 没有长度验证
if (
  (key === 'name' ||
    key === 'nickname' ||  // 没有长度限制
    // ...
  ) &&
  value !== null &&
  value !== undefined
) {
  if (typeof value !== 'string') {
    throw new AppError(/* ... */);
  }
  acc[key] = value;
}
```

**前端现状**:
```typescript
// src/types/api.ts
export interface UpdateProfilePayload {
    name?: string;
    nickname?: string;  // 没有长度限制
    avatar?: string;
    grade?: string;
    age?: number;
    school?: string;
}
```

**修复建议**:
```typescript
// 后端添加 nickname 长度验证
if (key === 'nickname') {
  if (typeof value !== 'string') {
    throw new AppError(
      400,
      'INVALID_PARAMS',
      '参数类型错误',
      { errors: [{ field: 'nickname', message: 'nickname 必须为字符串' }] }
    );
  }
  if (value.length < 2 || value.length > 20) {
    throw new AppError(
      400,
      'INVALID_PARAMS',
      '昵称长度必须在 2~20 个字符之间',
      { errors: [{ field: 'nickname', message: 'nickname 长度必须在 2~20 之间' }] }
    );
  }
  acc.nickname = value;
}
```

### 问题 95：GET /users/me/likes 和 GET /users/me/favorites 缺少响应类型定义

**优先级**: 低

**问题描述**:
前端 `profileService` 的 `getMyLikes` 和 `getMyFavorites` 方法虽然正确使用了 `ApiResponse` 类型，但返回的 `data.data`（即 `list` 和 `pagination`）没有专门的类型封装。

**前端现状**:
```typescript
// src/services/api.ts
export const profileService = {
    getMyLikes: async (params?: { page?: number; pageSize?: number }) => {
        const { data } = await api.get<
            ApiResponse<{
                list: MyLikedQuestion[];
                pagination: {
                    page: number;
                    pageSize: number;
                    total: number;
                    totalPages: number;
                };
            }>
        >('/users/me/likes', { params });
        return data.data;
    },
    getMyFavorites: async (params?: { page?: number; pageSize?: number }) => {
        const { data } = await api.get<
            ApiResponse<{
                list: MyFavoritedQuestion[];
                pagination: {
                    page: number;
                    pageSize: number;
                    total: number;
                    totalPages: number;
                };
            }
        >('/users/me/favorites', { params });
        return data.data;
    }
};
```

**修复建议**:
```typescript
// 前端添加分页响应类型
export interface PaginatedResponse<T> {
    list: T[];
    pagination: {
        page: number;
        pageSize: number;
        total: number;
        totalPages: number;
    };
}

// 使用
export const profileService = {
    getMyLikes: async (params?: { page?: number; pageSize?: number }) => {
        const { data } = await api.get<
            ApiResponse<PaginatedResponse<MyLikedQuestion>>
        >('/users/me/likes', { params });
        return data.data;
    },
    getMyFavorites: async (params?: { page?: number; pageSize?: number }) => {
        const { data } = await api.get<
            ApiResponse<PaginatedResponse<MyFavoritedQuestion>>
        >('/users/me/favorites', { params });
        return data.data;
    }
};
```

## 优化建议

### 短期优化（高优先级）

1. **PATCH /users/me 响应补充 expiresAt 和 classHours**: 确保更新用户信息后能获取最新课时状态
2. **添加前端 getUserInfo 方法**: 完善 userService 的 API 封装

### 中期优化（中优先级）

1. **统一错误消息格式**: age 字段验证失败消息与其他字段保持一致
2. **添加 nickname 长度限制**: 限制昵称 2-20 字符

### 长期优化（低优先级）

1. **添加 PaginatedResponse 泛型类型**: 统一分页响应结构
2. **补充 isValidMember 和 permissions 计算逻辑**: 或者从 User 类型中移除

---

## 总结

user-me（用户信息管理）模块整体功能完整，但存在以下问题：
1. `PATCH /users/me` 响应缺少 `expiresAt` 和 `classHours` 字段
2. 前端缺少 `getUserInfo` 专用方法
3. `PATCH /users/me` 错误消息格式不统一
4. `nickname` 字段缺少长度限制

建议按优先级逐步修复响应结构和类型定义，确保前后端数据结构一致。
