## 摘要

`src/services/api.ts` 是前端服务层的核心文件，承担了所有 API 调用逻辑。当前文件规模达到 **1232 行**，存在以下问题：

| 问题                | 影响                                    |
| ------------------- | --------------------------------------- |
| 单一文件过大        | 难以维护、协作冲突                      |
| 混合关注点          | Auth、Question、Notification 等逻辑混杂 |
| Mock 与真实逻辑混合 | 代码复杂度高                            |
| 测试困难            | 单文件测试用例难以组织                  |

**核心建议**：按业务域拆分为 **6 个独立文件**，并重构 Mock 逻辑。

## 拆分方案

### 方案对比

| 方案         | 文件数 | 复杂度 | 风险 | 适用场景 |
| ------------ | ------ | ------ | ---- | -------- |
| **保守拆分** | 5      | 低     | 低   | 快速迭代 |
| **推荐拆分** | 6      | 中     | 中   | 平衡     |
| **激进拆分** | 8+     | 高     | 高   | 长期维护 |

---

### 方案一：保守拆分（5文件）

```
src/services/
├── api.ts              # Axios 实例 + 拦截器（保留核心）
├── auth.ts             # authService + userService
├── question.ts         # questionService
├── interaction.ts       # interactionService + behaviorService
└── notification.ts     # notificationService + configService + profileService + adminService + auditService + answerService + commentService + classHoursService
```

**问题**：最后一个文件仍然过大，失去拆分意义。

---

### 方案二：推荐拆分（6文件）

```
src/services/
├── api.ts              # Axios 实例 + 拦截器
├── auth.ts             # 认证服务
├── question.ts         # 问题服务（最大，优先拆分）
├── interaction.ts      # 互动服务
├── notification.ts      # 通知服务
└── user.ts             # 用户 + 个人中心 + 管理功能
```

**优点**：

- 每个文件规模适中（200-500行）
- 业务边界清晰
- 变更影响可控

---

### 方案三：激进拆分（8文件）

```
src/services/
├── api.ts              # Axios 实例 + 拦截器
├── auth.ts             # 认证服务
├── question.ts         # 问题服务
├── interaction.ts      # 点赞/收藏
├── notification.ts     # 通知服务
├── user.ts            # 用户 + 个人中心
├── admin.ts           # 管理功能（admin + audit）
└── upload.ts          # 图片上传逻辑（从 questionService 提取）
```

**优点**：

- 职责单一
- 测试友好

**缺点**：

- 文件数过多
- 协作成本增加

#### 2. auth.ts（~50行）

```typescript
import { api } from './api';
import type {
  ApiResponse,
  LoginPayload,
  LoginResponse,
  PasswordLoginPayload,
  SendCodePayload,
  SendCodeResponse,
  RegisterPayload,
  UpdateProfilePayload,
} from '@/types/api';
import type { User } from '@/types';

export const authService = {
  sendCode: async (payload: SendCodePayload) => {
    return api.post<ApiResponse<SendCodeResponse>>('/auth/send-code', payload);
  },
  login: async (payload: LoginPayload) => {
    return api.post<ApiResponse<LoginResponse>>('/auth/login', payload);
  },
  passwordLogin: async (payload: PasswordLoginPayload) => {
    return api.post<ApiResponse<LoginResponse>>('/auth/password-login', payload);
  },
  register: async (payload: RegisterPayload) => {
    const { data } = await api.post<ApiResponse<LoginResponse>>('/auth/register', payload);
    return data.data;
  },
  setPassword: async (newPassword: string) => {
    return api.post<ApiResponse<null>>('/auth/set-password', { newPassword });
  },
};

export const userService = {
  updateProfile: async (data: UpdateProfilePayload) => {
    const { data: res } = await api.patch<ApiResponse<User>>('/users/me', data);
    return res.data;
  },
};
```

## Mock处理策略

### 问题

当前 Mock 逻辑与真实请求混在一起：

```typescript
// api.ts:108-424
if (USE_MOCK && import.meta.env.MODE === 'test') {
  api.interceptors.request.use(async (config) => {
    // 300+ 行 Mock 逻辑
    if (url.includes('/auth/send-code') && method === 'post') {
      /*...*/
    }
    if (url.includes('/auth/login') && method === 'post') {
      /*...*/
    }
    // ... 20+ 个分支
  });
}
```

### 方案对比

| 方案               | 优点               | 缺点       | 推荐度  |
| ------------------ | ------------------ | ---------- | ------- |
| **保持现状**       | 改动最小           | 复杂度高   | ❌      |
| **独立 Mock 文件** | 分离关注点         | 需同步更新 | ✅ 推荐 |
| **MSW**            | 社区标准、功能强大 | 学习成本   | ⚠️ 考虑 |

---

### 推荐：独立 Mock 文件

```
src/services/
├── mocks/
│   ├── index.ts              # Mock 入口
│   ├── auth.mock.ts
│   ├── question.mock.ts
│   ├── interaction.mock.ts
│   └── notification.mock.ts
├── api.ts
├── auth.ts
└── ...
```

**index.ts 示例**：

```typescript
import { api } from './api';
import { authMock } from './auth.mock';
import { questionMock } from './question.mock';

// 按需注册 Mock
if (USE_MOCK) {
  authMock.register(api);
  questionMock.register(api);
}
```

---

### 备选：MSW (Mock Service Worker)

```typescript
// src/services/mocks/worker.ts
import { setupWorker, rest } from 'msw';

export const worker = setupWorker(
  rest.post('/api/auth/login', (req, res, ctx) => {
    return res(ctx.json({ code: 200, data: mockUser }));
  }),
  // ... 其他 handlers
);

// 在 main.ts 中启用
if (USE_MOCK) {
  worker.start();
}
```

**优点**：

- 符合社区标准
- 支持网络层拦截
- 便于调试

**缺点**：

- 学习成本
- 配置工作

## 实施步骤

### Phase 1：创建新文件结构（低风险）

1. 创建 `src/services/auth.ts`，复制 authService + userService
2. 创建 `src/services/question.ts`，复制 questionService
3. 创建 `src/services/interaction.ts`，复制 interactionService + behaviorService
4. 创建 `src/services/notification.ts`，复制 notificationService + configService
5. 创建 `src/services/user.ts`，复制其余服务

**验证**：确保所有导入路径正确，编译通过。

---

### Phase 2：重构 Mock 逻辑（中等风险）

1. 创建 `src/services/mocks/index.ts`
2. 逐步迁移 Mock 逻辑到独立文件
3. 保留 `api.ts` 中的拦截器入口

**验证**：单元测试通过。
