# 前后端接口差异分析 10.0

> 本文档记录 comment（评论）模块的前后端接口字段一致性分析结果。

## 模块健康度评估

| 维度 | 评分 | 说明 |
|------|------|------|
| 接口完整性 | ⚠️ 中等 | 列表接口缺少 aiAudit 字段 |
| 类型安全性 | ⚠️ 中等 | 列表返回项缺少审核信息字段 |
| 参数字段一致性 | ✅ 良好 | 参数命名和类型基本一致 |

## 发现的问题

### 问题 106：GET /questions/:id/comments 缺少 aiAudit 字段

**优先级**: 高

**问题描述**:
前端 `Comment` 类型定义了 `aiAudit?: { safe: boolean; reason?: string }` 字段，但后端 `GET /questions/:id/comments` 列表接口返回的数据中没有包含 `aiAudit` 字段。这导致前端在展示评论列表时无法获取每条评论的结构化 AI 审核状态。

**后端现状**:
```typescript
// backend/src/services/comment.service.ts - list 方法返回项
return {
  id: c.id,
  questionId: c.questionId,
  content: c.content,
  image: c.image ?? undefined,
  authorId: c.authorId,
  authorName: c.authorName,
  authorAvatar: c.authorAvatar ?? undefined,
  status: c.status,
  aiResult: c.aiResult ?? undefined,
  createdAt: c.createdAt
  // ❌ 缺少 aiAudit
};
```

**对比 POST /questions/:id/comments 返回**:
```typescript
// backend/src/services/comment.service.ts - create 方法返回
return {
  id: created.id,
  questionId: created.questionId,
  content: created.content,
  image: created.image ?? undefined,
  authorId: created.authorId,
  authorName: created.authorName,
  authorAvatar: created.authorAvatar ?? undefined,
  status: created.status,
  aiResult: created.aiResult ?? undefined,
  createdAt: created.createdAt,
  // ✅ 返回审核结果供前端显示
  aiAudit: {
    safe: auditResult.safe,
    reason: auditResult.reason
  }
};
```

**前端现状**:
```typescript
// src/types/index.ts
export interface Comment {
  id: string;
  questionId: string;
  questionTitle?: string;
  content: string;
  image?: string;

  authorId: string;
  authorName: string;
  authorAvatar?: string;

  status: AuditStatus;
  aiResult?: string;
  aiAudit?: {
    safe: boolean;
    reason?: string;
  };
  createdAt: string;
}
```

**修复建议**:
```typescript
// 后端 list 方法补充 aiAudit
return {
  id: c.id,
  questionId: c.questionId,
  content: c.content,
  image: c.image ?? undefined,
  authorId: c.authorId,
  authorName: c.authorName,
  authorAvatar: c.authorAvatar ?? undefined,
  status: c.status,
  aiResult: c.aiResult ?? undefined,
  createdAt: c.createdAt,
  aiAudit: (() => {
    if (c.aiResult && c.aiResult !== '无违规') {
      try {
        const result = JSON.parse(c.aiResult);
        return { safe: result.safe ?? true, reason: result.reason };
      } catch {
        return undefined;
      }
    }
    return undefined;
  })()
};
```

### 问题 108：前端 commentService.create 缺少专门的有效载荷类型

**优先级**: 低

**问题描述**:
前端 `commentService.create` 方法的 `payload` 参数使用了内联类型 `{ content?: string; image?: string }`，没有创建专门的类型定义。相比之下，其他服务（如 `questionService`）使用了 `CreateQuestionPayload` 这样的专门类型。

**前端现状**:
```typescript
// src/services/api.ts
export const commentService = {
    create: async (
        questionId: string,
        payload: { content?: string; image?: string }  // ❌ 内联类型
    ) => {
        const { data } = await api.post<ApiResponse<Comment>>(
            `/questions/${questionId}/comments`,
            payload
        );
        return data.data;
    },
    listByQuestion: async (questionId: string) => {
        const { data } = await api.get<
            ApiResponse<{ list: Comment[]; total: number }>
        >(`/questions/${questionId}/comments`);
        return data.data;
    }
};
```

**修复建议**:
```typescript
// 前端添加 CreateCommentPayload 类型
export interface CreateCommentPayload {
    content?: string;
    image?: string;
}

// 使用
export const commentService = {
    create: async (questionId: string, payload: CreateCommentPayload) => {
        const { data } = await api.post<ApiResponse<Comment>>(
            `/questions/${questionId}/comments`,
            payload
        );
        return data.data;
    },
    // ...
};
```

### 问题 109：后端 listByQuestion 缺少作者角色信息返回

**优先级**: 低

**问题描述**:
前端 `Comment` 类型中没有定义 `authorRole` 字段，但后端 `comment.service.ts` 在创建评论时实际上拥有作者的角色信息。后端列表接口返回的数据中也缺少 `authorRole` 字段，可能影响前端根据作者角色展示不同 UI（如教师评论显示特殊标识）。

**后端现状**:
```typescript
// backend/src/services/comment.service.ts - list 方法返回项
return {
  id: c.id,
  questionId: c.questionId,
  content: c.content,
  image: c.image ?? undefined,
  authorId: c.authorId,
  authorName: c.authorName,
  authorAvatar: c.authorAvatar ?? undefined,
  status: c.status,
  aiResult: c.aiResult ?? undefined,
  createdAt: c.createdAt
  // ❌ 缺少 authorRole
};
```

**前端现状**:
```typescript
// src/types/index.ts
export interface Comment {
  // ...
  authorId: string;
  authorName: string;
  authorAvatar?: string;
  // 没有定义 authorRole
  // ...
}
```

**问题分析**:
虽然前后端当前都没有定义 `authorRole`，但后端在创建评论时能够获取作者角色信息（从 `author.role` 获取）。如果未来需要展示评论者的身份标识（如教师/学生），建议在前后端同步添加该字段。

**修复建议**:
```typescript
// 前端 Comment 类型补充 authorRole
export interface Comment {
  id: string;
  questionId: string;
  questionTitle?: string;
  content: string;
  image?: string;

  authorId: string;
  authorName: string;
  authorAvatar?: string;
  authorRole?: string;  // ✅ 添加

  status: AuditStatus;
  aiResult?: string;
  aiAudit?: {
    safe: boolean;
    reason?: string;
  };
  createdAt: string;
}

// 后端 list 方法补充 authorRole
const comments = await prisma.comment.findMany({
  where: {
    questionId,
    status: 'approved',
    deletedAt: null
  },
  orderBy: {
    createdAt: 'desc'
  },
  include: {
    author: {
      select: { role: true }
    }
  }
});

return {
  list: comments.map((c) => ({
    id: c.id,
    questionId: c.questionId,
    content: c.content,
    image: c.image ?? undefined,
    authorId: c.authorId,
    authorName: c.authorName,
    authorAvatar: c.authorAvatar ?? undefined,
    authorRole: c.author.role,  // ✅ 添加
    status: c.status,
    aiResult: c.aiResult ?? undefined,
    createdAt: c.createdAt
  })),
  total: comments.length
};
```

## 优化建议

### 短期优化（高优先级）

1. **GET /questions/:id/comments 补充 aiAudit**: 确保评论列表接口返回完整的 AI 审核信息
2. **POST /questions/:id/comments 补充 questionTitle**: 如业务需要，通过关联查询获取问题标题

### 中期优化（中优先级）

1. **创建 CreateCommentPayload 专门类型**: 统一前端有效载荷类型定义
2. **创建 CommentListResponse 专门类型**: 统一前端列表响应类型

### 长期优化（低优先级）

1. **前后端同步添加 authorRole**: 为未来作者身份展示做准备
2. **考虑添加评论分页功能**: 当前一次性返回所有评论可能影响性能

---

## 总结

comment（评论）模块核心功能完整，但存在以下不一致问题：
1. `GET /questions/:id/comments` 列表接口缺少 `aiAudit` 字段
2. `POST /questions/:id/comments` 和列表接口都缺少 `questionTitle` 字段
3. 前后端都缺少 `authorRole` 字段用于展示作者身份
4. 前端缺少 `CreateCommentPayload` 和 `CommentListResponse` 专门类型

建议按优先级逐步修复，确保各接口返回的数据结构一致，提升前端开发体验和数据可预测性。

### 问题 111：listUserLikes/listUserFavorites pagination.total 与 list 长度可能不一致

**优先级**: 高

**问题描述**:
后端 `interactionService.listUserLikes` 和 `listUserFavorites` 方法在返回数据时，使用 `.filter(Boolean)` 移除了无效项（如问题已被删除），但 `pagination.total` 是基于数据库查询的原始计数。这导致前端收到的 `list` 长度可能小于 `pagination.total`，造成分页信息不准确。

**后端现状**:
```typescript
// backend/src/services/interaction.service.ts - listUserLikes
return {
  list: likes
    .map((l) => {
      const q = map.get(l.targetId);
      if (!q) return null;
      return {
        // ... 返回字段
      };
    })
    .filter(Boolean),  // ❌ 可能移除项，导致 list 长度小于 total
  pagination: {
    page,
    pageSize: safePageSize,
    total,  // ❌ 基于原始 likes 计数，可能与 list 长度不一致
    totalPages: Math.ceil(total / safePageSize)
  }
};
```

**问题分析**:
当一个问题被删除后，用户的点赞/收藏记录仍然存在于 `like` 或 `favorite` 表中，但关联的 `question` 可能已被删除。这种情况下，`.filter(Boolean)` 会移除这些无效项，但 `total` 计数包含了这些已删除的问题。

**修复建议**:
```typescript
// 方案1：过滤后重新计算 total
const filteredList = likes
  .map((l) => {
    const q = map.get(l.targetId);
    if (!q) return null;
    return {
      id: q.id,
      title: q.title,
      content: q.content,
      authorName: q.authorName,
      authorAvatar: q.authorAvatar ?? undefined,
      likes: q.likes,
      favorites: q.favorites,
      answers: q.answers,
      createdAt: q.createdAt,
      likedAt: l.createdAt
    };
  })
  .filter(Boolean);

return {
  list: filteredList,
  pagination: {
    page,
    pageSize: safePageSize,
    total: filteredList.length,  // ✅ 使用过滤后的长度
    totalPages: Math.ceil(filteredList.length / safePageSize)
  }
};

// 方案2：在查询时排除已删除问题（推荐）
const [likes, total] = await Promise.all([
  prisma.like.findMany({
    where: {
      userId,
      targetType: 'question',
      targetId: { in: questionIds }  // 只查询有关联问题的点赞
    },
    orderBy: { createdAt: 'desc' },
    skip: (page - 1) * safePageSize,
    take: safePageSize
  }),
  // ...
]);
```

```typescript
// backend/src/routes/interaction.routes.ts
```

## 优化建议

### 短期优化（高优先级）

1. **修复 pagination.total 与 list 长度不一致问题**: 过滤后重新计算 total，确保分页信息准确
2. **统一 isLiked/liked 命名**: 建议后端改为 liked，与前端保持一致

### 中期优化（中优先级）

1. **前后端同步添加 authorRole**: 为未来作者身份展示做准备
2. **添加 comments 字段**: 完善问题统计信息

### 长期优化（低优先级）

1. **预留 answer 点赞支持**: 前端类型改为联合类型
2. **考虑软删除机制**: 问题删除时同步清理点赞/收藏记录

## 总结

like/favorite（互动）模块整体功能完整，但存在以下问题：
1. `pagination.total` 与 `list` 长度可能不一致（高优先级）
2. `isLiked`/`liked` 命名不统一
3. 前后端都缺少 `authorRole` 和 `comments` 字段
4. 缺少答案点赞功能扩展性准备

建议按优先级逐步修复，确保各接口返回的数据结构一致，提升前端开发体验和数据可预测性。
