## 发现的问题

### ⚠️ 47. 待审核问题列表返回冗余字段

**问题：** 后端 `images` 字段始终返回空数组

**后端代码：**
```typescript
// backend/src/services/audit.service.ts (行 72-82)
list: list.map((q) => ({
    id: q.id,
    type: 'question' as const,
    title: q.title,
    content: q.content ?? '',
    images: [],  // ⚠️ 始终为空数组
    authorId: q.authorId,
    // ...
}))
```

**问题分析：**
| 对比 | 说明 |
|------|------|
| 数据库 | `question` 表没有 `images` 字段 |
| 返回值 | 始终返回 `[]` |
| 前端 | 未定义此字段 |

**影响：** 无功能影响，但浪费带宽和前端解析资源

---

### ⚠️ 49. rejectQuestion 响应字段命名不精确

**问题：** `rejectReason` 取值来源不明确

**后端返回：**
```typescript
// backend/src/routes/admin-audit.routes.ts (行 156-163)
return res.json({
    code: 200,
    message: '审核完成：已驳回',
    data: {
        id: updated.id,
        status: updated.status,
        rejectReason: updated.aiResult,  // ⚠️ aiResult 存储的是 AI 审核结果
        rejectedBy: req.user!.id,
        rejectedAt: updated.updatedAt
    },
    timestamp: Date.now()
});
```

**问题分析：**
| 字段 | 返回值 | 说明 |
|------|--------|------|
| `rejectReason` | `updated.aiResult` | AI 审核结果/驳回原因 |
| `rejectedAt` | `updated.updatedAt` | 更新时间 |

**建议改进：**
```typescript
data: {
    id: updated.id,
    status: updated.status,
    reason: updated.aiResult,  // 简化命名
    rejectedBy: req.user!.id,
    rejectedAt: updated.updatedAt
}
```

### 2. 批量行为日志上报（前端实现，后端缺失）

#### 前端实现

```typescript
// src/services/api.ts
batchLog: async (events: Array<{ type: string; timestamp: number; metadata?: any }>) => {
    let processed = 0;
    let failed = 0;

    for (const event of events) {
        try {
            await api.post<ApiResponse<unknown>>('/behavior/log', {
                type: event.type,
                timestamp: event.timestamp,
                metadata: event.metadata
            });
            processed += 1;
        } catch {
            failed += 1;
        }
    }

    return {
        received: events.length,
        processed,
        failed
    };
}
```

#### 问题分析

| 对比项 | 说明 |
|--------|------|
| 前端 | 有 `batchLog` 函数 |
| 后端 | ❌ **没有批量接口** |
| 当前行为 | 循环调用单条接口，性能差 |
| 实际效果 | 串行上传 N 次，耗时长 |

## 发现的问题

### ⚠️ 52. 前端 batchLog 是伪批量实现

**问题：** 前端声称支持批量上传，实际是循环调用单条接口

**前端代码：**
```typescript
// src/services/api.ts
batchLog: async (events: Array<{ type: string; timestamp: number; metadata?: any }>) => {
    for (const event of events) {  // ⚠️ 循环串行调用
        await api.post('/behavior/log', { ... });
    }
    return { received, processed, failed };
}
```

**后端现状：**
```typescript
// backend/src/routes/behavior.routes.ts
// 只有单条接口
behaviorRouter.post('/log', async (req, res, next) => {
    // 处理单条
});
```

**影响：**
| 问题 | 影响 |
|------|------|
| 性能差 | N 次 HTTP 请求，而非 1 次 |
| 耗时长 | 串行等待，延迟累积 |
| 流量大 | 头部开销 N 倍 |

**建议方案：**
```typescript
// 新增后端批量接口
POST /behavior/log/batch
Request: { events: Array<{ type, timestamp, metadata }> }
Response: { successCount, failedCount, results: Array<{ index, logId, error }> }
```

**后端支持：**
```typescript

async logSingle(params: {

```

**前端调用：**
```typescript

    authorId

```

**影响：** 无法进行单会话内的行为序列分析

### ⚠️ 54. behaviorService 缺乏类型定义

**问题：** `behaviorService` 函数没有明确的参数和返回类型

**前端现状：**
```typescript
// src/services/api.ts
export const behaviorService = {
    log: async (type: string, metadata?: Record<string, any>) => {
        const { data } = await api.post<ApiResponse<{ logId: string }>>('/behavior/log', {
            type,
            timestamp: Date.now(),
            metadata
        });
        return data.data;
    },
    batchLog: async (events: Array<{ type: string; timestamp: number; metadata?: any }>) => {
        // ...
    }
}
```

**建议类型定义：**
```typescript
// src/types/api.ts

export interface BehaviorLogParams {
    type: string;
    timestamp?: number;
    metadata?: Record<string, unknown>;
    sessionId?: string;
}

export interface BehaviorLogResult {
    logId: string;
}

export interface BehaviorBatchResult {
    received: number;
    processed: number;
    failed: number;
}

export interface BehaviorService {
    log: (type: string, metadata?: Record<string, any>) => Promise<BehaviorLogResult>;
    batchLog: (events: BehaviorLogParams[]) => Promise<BehaviorBatchResult>;
}
```

### ⚠️ 55. 前端隐式传递 path 和 referrer

**问题：** 前端未显式传递 `path` 和 `referrer`，后端从 `metadata` 中提取

**当前实现：**
```typescript
// backend/src/routes/behavior.routes.ts
const created = await behaviorLogService.logSingle({
    userId,
    type,
    timestamp,
    metadata,
    path: metadata?.path ?? req.path,  // ⚠️ 从 metadata 提取
    referrer: metadata?.referrer,      // ⚠️ 从 metadata 提取
    // ...
});
```

**前端调用示例：**
```typescript
// src/pages/QuestionDetailPage.tsx
await behaviorService.log('question_like', {
    questionId: id,
    authorId,
    // path: window.location.pathname,  // ❌ 没传
    // referrer: document.referrer     // ❌ 没传
});
```

**建议前端显式传递：**
```typescript
behaviorService.log('question_like', {
    questionId: id,
    authorId,
    path: window.location.pathname,
    referrer: document.referrer
});
```

// backend/src/routes/behavior.routes.ts

// 批量行为日志上报
behaviorRouter.post(
  '/log/batch',
  async (req: Request, res: Response, next: NextFunction) => {
    try {
      const { events } = req.body as { events?: Array<{ type: string; timestamp?: number; metadata?: any }> };

      if (!Array.isArray(events) || events.length === 0) {
        throw new AppError(400, 'VALIDATION_ERROR', 'events 必须是非空数组');
      }

      if (events.length > 100) {
        throw new AppError(400, 'VALIDATION_ERROR', '单次批量最多 100 条');
      }

      const results: Array<{ index: number; logId?: string; error?: string }> = [];

      for (let i = 0; i < events.length; i++) {
        try {
          const created = await behaviorLogService.logSingle({
            type: events[i].type,
            timestamp: events[i].timestamp,
            metadata: events[i].metadata,
            path: events[i].metadata?.path,
            referrer: events[i].metadata?.referrer
          });
          results.push({ index: i, logId: created.id });
        } catch (err: any) {
          results.push({ index: i, error: err.message });
        }
      }

      return res.json({
        code: 200,
        message: 'success',
        data: {
          successCount: results.filter(r => r.logId).length,
          failedCount: results.filter(r => r.error).length,
          results
        },
        timestamp: Date.now()
      });
    } catch (err) {
      next(err);
    }
  }
);
