## 发现的问题

### ⚠️ 功能限制未同步

**位置：** [backend/src/routes/interaction.routes.ts:55-57](../../backend/src/routes/interaction.routes.ts#L55-L57)

**问题描述：**
- 后端目前 **只支持** `targetType='question'`
- 前端类型定义却允许 `'answer'`

**后端代码：**
```typescript
if (targetType !== 'question') {
  throw new AppError(
    400,
    'UNSUPPORTED_TARGET_TYPE',
    '当前仅支持问题点赞'
  );
}
```

**前端类型定义：**
```typescript
// src/types/api.ts
export interface LikePayload {
  targetType: 'question' | 'answer';  // 预留了 answer 支持
  targetId: string;
  action: 'like' | 'unlike';
}
```

**影响：**
- 前端为未来扩展预留了 `answer` 类型支持
- 但后端尚未实现回答点赞功能
- 如果未来需要支持回答点赞，后端验证逻辑需要同步更新

## 发现的问题

### ❌ 1. 查询参数命名不一致

**问题：** `pageSize` vs `limit`，`tags` vs `topic`

**后端代码：**
```typescript
// backend/src/routes/question.routes.ts
const { page, pageSize, status, isGoodQuestion, tags, authorId, search } = req.query as any;
```

**前端类型：**
```typescript
// src/types/api.ts
export interface QuestionListParams {
    page?: number;
    limit?: number;      // ❌ 与后端 pageSize 不一致
    subject?: string;
    topic?: string;      // ❌ 与后端 tags 不一致
    method?: string;     // ❌ 后端没有这个参数
    search?: string;
    authorId?: string;
}
```

**影响：**
- 前端传递 `limit` 但后端期望 `pageSize`
- 前端传递 `topic` 但后端期望 `tags`
- 这些参数**可能无法正常工作**，需要检查实际调用

---

### ❌ 2. 前端类型定义缺失关键字段

**问题：** 前端 `Question` 类型和 `CreateQuestionPayload` 缺少后端返回的字段

**缺失字段列表：**
| 类型 | 缺失字段 |
|------|----------|
| `CreateQuestionPayload` | `authorAvatar`（请求中不需要，但响应有） |
| `CreateQuestionPayload` | `audioUrl`（类型定义缺失） |
| `Question` | `authorAvatar` |
| `Question` | `authorRole` |
| `Question` | `isLiked` |
| `Question` | `isFavorited` |
| `Question` | `score` |
| `Question` | `aiResult` |

**前端响应转换代码：**
```typescript
// src/services/api.ts

// 直接将后端数据赋给 Question 类型，但 Question 类型缺少这些字段！
```

## 发现的问题

### ❌ 1. 验证码类型不完整

**问题：** 前端 `SendCodePayload.type` 只支持 `'login' \| 'register'`，但后端支持更多类型

**后端代码：**
```typescript
// backend/src/services/auth.service.ts
type SendCodeType = 'login' | 'register' | 'bind_child' | 'reset_password';
```

**前端类型：**
```typescript
// src/types/api.ts
export interface SendCodePayload {
    phone: string;
    type?: 'login' | 'register';  // ❌ 缺少 bind_child 和 reset_password
}
```

**影响：**
- 前端无法发起 `bind_child`（绑定孩子）和 `reset_password`（重置密码）的验证码请求
- 这两个功能的验证码发送会失败或类型错误

---

### ❌ 2. 登录响应缺少 refreshToken

**问题：** 前端 `LoginResponse` 没有定义 `refreshToken` 字段

**后端返回：**
```typescript
// backend/src/services/auth.service.ts
return {
    token,
    refreshToken,  // ✅ 返回了 refreshToken
    user: {...}
};
```

**前端类型：**
```typescript
// src/types/api.ts
export interface LoginResponse {
    token: string;
    user: User;  // ❌ 没有 refreshToken
}
```

**影响：**
- 前端无法使用 refreshToken 刷新访问令牌
- Token 过期后需要重新登录，用户体验差

---

### ❌ 3. 发送验证码响应类型缺失

**问题：** 前端没有定义发送验证码的响应类型

**后端返回：**
```typescript
// backend/src/services/auth.service.ts
return {
    phone: normalizedPhone,
    expireIn: CODE_EXPIRE_SECONDS,  // 300 秒
    cooldown: SEND_COOLDOWN_SECONDS  // 60 秒
};
```

**前端没有对应的类型定义**，无法进行类型检查

---

### ❌ 4. User 类型缺少可选字段

**问题：** 后端登录响应中 `expiresAt`、`isValidMember`、`permissions` 可能返回 `undefined`，但前端 User 类型没有这些字段

**后端代码：**
```typescript
// backend/src/services/auth.service.ts
return {
    ...
    user: {
        ...
        expiresAt: undefined,          // ❌ 前端 User 类型没有这个字段
        isValidMember: undefined,      // ❌ 前端 User 类型没有这个字段
        permissions: undefined        // ❌ 前端 User 类型没有这个字段
    }
};
```

**前端 User 类型：**
```typescript
// src/types/index.ts
export interface User {
    id: string;
    phone: string;
    name?: string;
    nickname: string;
    avatar?: string;
    role: string;
    // ❌ 缺少 expiresAt, isValidMember, permissions
}
```

---

### ❌ 5. 验证码响应类型未定义

**问题：** 前端没有定义 `SendCodeResponse` 类型

**后端返回类型：**
