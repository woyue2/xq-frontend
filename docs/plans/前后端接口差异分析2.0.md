## 发现的问题

### ❌ 1. 获取用户信息缺少 classHours 字段

**问题：** 后端返回了 `classHours` 字段，但前端 `User` 类型没有定义

**后端代码：**
```typescript
// backend/src/routes/user-me.routes.ts
return res.json({
    data: {
        ...
        classHours  // ✅ 返回了课时信息
    }
});
```

**前端类型：**
```typescript
// src/types/index.ts
export interface User {
    id: string;
    phone: string;
    ...
    // ❌ 缺少 classHours
}
```

**影响：**
- 前端无法类型检查课时信息
- 页面展示课时余额时可能出错

---

### ❌ 2. 更新用户信息缺少类型约束

**问题：** 前端使用 `Partial<User>` 作为更新参数类型，包含了后端不允许修改的字段

**前端代码：**
```typescript
// src/services/api.ts
export const userService = {
    updateProfile: async (data: Partial<User>) => {
        // ❌ Partial<User> 包含 id, phone, role, expiresAt 等不允许更新的字段
        const { data: res } = await api.patch<ApiResponse<User>>('/users/me', data);
        return res.data;
    }
};
```

**后端代码：**
```typescript
// backend/src/routes/user-me.routes.ts
const allowedFields = ['name', 'nickname', 'avatar', 'grade', 'age', 'school'];
// ❌ 只允许更新这 6 个字段
```

**影响：**
- TypeScript 无法在编译期发现不允许的字段被传入
- 可能发送不必要的请求数据
- 建议定义专门的 `UpdateProfilePayload` 类型

---

### ⚠️ 6. 前端 User 类型存在冗余字段

**问题：** 前端 `User` 类型定义了 `isValidMember` 和 `permissions` 字段，但后端登录响应中这些字段始终返回 `undefined`

**前端代码：**
```typescript
// src/types/index.ts
export interface User {
    ...
    expiresAt?: string;
    isValidMember?: boolean;   // ❌ 后端不返回
    permissions?: string[];     // ❌ 后端不返回
}
```

**后端代码：**
```typescript
// backend/src/services/auth.service.ts
return {
    ...
    user: {
        ...
        isValidMember: undefined,      // ❌ 始终 undefined
        permissions: undefined        // ❌ 始终 undefined
    }
};
```

**影响：**
- TypeScript 可能误以为这些字段有值
- 建议移除或明确注释这些字段的来源
