# 后端使用风险分析（基于结构审计）

- 生成时间：2026-02-13
- 依据文档：`docs/backend-structure-audit-2026-02-13.md`
- 说明：聚焦“可能影响实际使用”的风险，不包含改造方案。

## 高优先级风险（最可能影响用户体验）

1. 路由层业务逻辑过重且直连数据库（`question.routes.ts`）
- 现象：同一文件同时承担权限矩阵、状态流转、事务、数据组装。
- 使用影响：不同入口对同一业务规则可能出现不一致（如可见性、权限、状态判断），导致用户感知“同功能在不同页面行为不一致”。

2. AI 回调链路在路由层直接改状态（`internal.routes.ts`）
- 现象：回调接口直接进行多表状态更新。
- 使用影响：当回调与主业务链路规则出现偏差时，可能出现审核结果与前台展示、通知、统计不一致。

3. 同一业务同时存在 Route 调 Service 与 Route 直连 Prisma（跨层混用）
- 现象：`question/internal/profile/user-me/comment` 等路由存在混合访问模式。
- 使用影响：边界条件下更容易出现“部分成功/部分失败”与数据口径分裂，导致列表与详情不一致。

4. 点赞/收藏存在双入口路径（`/questions/:id/like|favorite` 与 `/interactions/like|favorite`）
- 现象：两个 HTTP 入口承载同类动作。
- 使用影响：若契约字段/状态处理微小偏差，会出现页面刷新后状态回跳、计数口径不一致等问题。

## 中优先级风险（易在迭代中累积为故障）

5. 用户侧列表聚合逻辑在路由层实现（`profile.routes.ts`、`user-me.routes.ts`）
- 现象：路由层包含分页兜底、字段过滤、结果拼装。
- 使用影响：统计口径（`total`、分页、过滤条件）在不同列表容易漂移，出现“数字不准/条目不一致”。

6. 埋点限流在路由层使用内存 Map（`behavior.routes.ts`）
- 现象：防刷状态驻留进程内存。
- 使用影响：多实例或重启环境下限流行为不稳定，可能导致有时误限流（429），有时限流失效。

7. 上传链路强依赖本地文件系统（`upload.routes.ts`）
- 现象：音频上传落盘与静态目录映射依赖运行节点本地路径。
- 使用影响：分布式/容器部署时易出现“上传成功但访问404/跨节点文件不可见”。

## 低优先级风险（当前可用，但存在隐患）

8. 校验逻辑分散在多层（Route 与 Service 双处校验）
- 现象：参数与权限规则在不同层重复出现。
- 使用影响：规则更新时易漏改，产生局部请求放行/拦截不一致。

9. 复杂度集中在少数核心路由文件
- 现象：`question/internal/user-me/behavior` 复杂度显著高于其他文件。
- 使用影响：需求变更的回归半径变大，线上“修A坏B”概率上升。

## 风险等级总结

- 影响使用的即时风险：中-高
- 规则一致性风险：高
- 统计/展示口径漂移风险：中-高
- 迭代引入回归风险：中
