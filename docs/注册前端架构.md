## 二、页面组件结构

### 1. LoginPage

**组件名称:** `LoginPage`

**使用的表单库:** 原生 `useState` + shadcn/ui 组件（Input, Button, Select, Label）

**表单字段列表:**

#### 通用字段（登录+注册）

|-------|------|------|--------|---------|------------------|

| code | input (password) | 登录(根据模式) / 注册(是) | 空 | 6位数字(后端验证) | 否 |
| password | input (password) | 登录(密码模式) / 注册(是) | 空 | 至少8位 | 否 |
| showPassword | - | - | false | - | 否 |

#### 注册专属字段

| 字段名 | 类型 | 必填 | 默认值 | 校验规则 | 受 role/邀请码影响 |
|-------|------|------|--------|---------|------------------|
| inviteCode | input | 是 | 空 | 必须在 validInviteCodes 列表中 | **是** - 根据邀请码判断角色 |
| name | input (text) | 是 | 空 | 非空字符串 | 否 |
| nickname | input (text) | 否 | 自动生成 `用户${phone.slice(-4)}` | - | 否 |

#### 学生注册专属字段（仅当邀请码为 STUDENT2024 或 ZHISHIXINGQIU2024 时显示）

| 字段名 | 类型 | 必填 | 默认值 | 校验规则 | 受 role/邀请码影响 |
|-------|------|------|--------|---------|------------------|
| grade | select | 是 | 空 | 必须在 ['初一', '初二', '初三'] 中 | **是** - 仅学生显示 |
| age | input (number) | 是 | 空 | 10-18岁整数 | **是** - 仅学生显示 |
| school | input (text) | 是 | 空 | 非空字符串 | **是** - 仅学生显示 |

#### 家长注册专属字段（仅当邀请码为 PARENT2024 时显示）

| 字段名 | 类型 | 必填 | 默认值 | 校验规则 | 受 role/邀请码影响 |
|-------|------|------|--------|---------|------------------|
| childName | input (text) | 是 | 空 | 非空字符串 | **是** - 仅家长显示 |
| childPhone | input (tel) | 是 | 空 | 11位数字 | **是** - 仅家长显示 |
| childCode | input (password) | 是 | 空 | 6位数字 | **是** - 仅家长显示 |
| childSchool | input (text) | 否 | 空 | - | **是** - 仅家长显示 |

**状态变量:**
- `isLogin`: boolean - 切换登录/注册模式
- `loginMode`: 'code' \| 'password' - 登录方式
- `countdown`: number - 验证码倒计时
- `childCountdown`: number - 孩子验证码倒计时
- `showPassword`: boolean - 密码可见性

**角色判断逻辑:**
```typescript

const isTeacherInvite = !isLogin && inviteCode === 'TEACHER2024';
```

## 三、注册流程时序

### 完整注册流程

```
Step 1: 用户访问 /login 页面
        - 默认显示登录模式（isLogin = true）
        - 用户点击"去注册"切换为注册模式（isLogin = false）

Step 2: 输入手机号
        - 自动限制为11位数字
        - 点击"获取验证码"按钮
        - 调用 POST /auth/send-code (type: 'register')
        - 开始60秒倒计时

Step 3: 输入验证码
        - 6位数字验证码

Step 4: 设置密码
        - 至少8位
        - 建议包含数字和字母

Step 5: 输入邀请码
        - 必填项
        - 必须在 validInviteCodes 列表中
        - 根据邀请码自动判断角色类型

Step 6: 填写角色专属信息
        - 学生：年级(select) + 年龄(number) + 学校(text)
        - 家长：孩子姓名 + 孩子手机号 + 孩子验证码 + 孩子学校(可选)
        - 老师：无额外字段

Step 7: 提交注册
        - 前端表单验证
        - 调用 POST /auth/register
        - 成功后自动登录（调用 useAuthStore.login）
        - Token 存储到 localStorage 和 Zustand store

Step 8: 注册完成
        - 跳转首页（家长需稍后手动绑定孩子）

Step 9: 跳转首页
        - navigate('/')
```

## 四、API 调用结构

### 1. 发送验证码

**请求方法:** POST

**URL:** `/auth/send-code`

**请求体字段:**

```typescript
interface SendCodePayload {
  phone: string;      // 手机号
  type?: 'login' | 'register' | 'bind_child' | 'reset_password';
}
```

**成功返回结构:**

```typescript
interface SendCodeResponse {
  phone: string;
  expireIn: number;   // 过期时间(秒)
  cooldown: number;   // 冷却时间(秒)
}
```

**失败处理方式:**
- 网络错误或验证失败由 axios 拦截器统一处理
- 显示 toast 错误提示
- 倒计时停止

**Token 存储:** 不需要

---

### 2. 用户注册

**请求方法:** POST

**URL:** `/auth/register`

**请求体字段:**

```typescript
interface RegisterPayload {
  phone: string;           // 手机号
  code: string;            // 验证码
  password: string;        // 密码（至少8位）
  name: string;            // 真实姓名（必填）
  nickname?: string;       // 昵称（可选，不填则自动生成）
  role?: 'student' | 'teacher' | 'parent';  // 角色（根据邀请码自动设置）
  grade?: string;          // 年级（仅学生）
  age?: number;            // 年龄（仅学生）
  school?: string;         // 学校（仅学生/家长可选）
}
```

**成功返回结构:**

```typescript
interface LoginResponse {
  token: string;           // JWT token
  refreshToken: string;    // 刷新令牌
  user: User;              // 用户信息
}
```

**失败处理方式:**
- 验证码错误、手机号已注册等由后端返回错误码
- axios 拦截器统一显示 toast 错误
- 不跳转，留在当前页面

**Token 存储:**
- 调用 `useAuthStore.login(user, token)` 存储到 Zustand store
- 同时写入 `localStorage.setItem('token', token)`
- Zustand persist 中间件会持久化到 `localStorage` 的 `auth-storage` 键

---

### 3. 家长绑定孩子

**请求方法:** POST

**URL:** `/parent/bind`

**请求体字段:**

```typescript
interface BindChildPayload {
  childName: string;   // 孩子姓名
  phone: string;       // 孩子手机号
  code: string;        // 孩子验证码
  school?: string;     // 孩子学校（可选）
}
```

**成功返回结构:**

```typescript
interface BindChildResponse {
  child: ChildInfo;
}
```

**失败处理方式:**
- try-catch 包裹，失败时显示 toast 错误
- 提示"绑定失败，请稍后重试"

**Token 存储:** 使用已登录状态的 token（需先登录）

## 五、页面跳转关系

```
LoginPage (登录模式)
  ├─ 登录成功 -> HomePage (首页)
  ├─ 验证码错误 -> 停留在 LoginPage (显示错误提示)
  └─ 密码错误 -> 停留在 LoginPage (显示错误提示)

LoginPage (注册模式)
  ├─ 注册成功 -> HomePage (首页)
  │    └─ 家长需在家长中心手动绑定孩子
  ├─ 邀请码无效 -> 停留在 LoginPage (显示错误提示)
  ├─ 表单验证失败 -> 停留在 LoginPage (显示错误提示)
  └─ 注册失败 -> 停留在 LoginPage (显示错误提示)
```

## 七、状态管理

### Zustand Store

**Store 名称:** `useAuthStore`

**位置:** `src/stores/useAuthStore.ts`

**状态结构:**

```typescript
interface AuthState {
  user: User | null;           // 用户信息
  token: string | null;        // JWT token
  isAuthenticated: boolean;   // 是否已认证
  isLoading: boolean;          // 加载状态
  isActiveMember: boolean;    // 是否活跃会员（衍生）
  permissions: Permission[];  // 权限列表（衍生）

  // Actions
  login: (user: User, token: string) => void;
  logout: () => void;
  updateUser: (updates: Partial<User>) => void;
}
```

**持久化配置:**
- 使用 `zustand/middleware` 的 `persist`
- 存储键名: `auth-storage`
- 存储介质: `localStorage`
- 持久化字段: `user`, `token`, `isAuthenticated`
- `isActiveMember` 和 `permissions` 不持久化（每次初始化重算）

**Token 存储位置:**
1. Zustand store (内存)
2. `localStorage.setItem('token', token)` (持久化)
3. `localStorage` 的 `auth-storage` (Zustand persist)

**读取 Token 优先级（在 api.ts 请求拦截器中）:**
1. 从 `useAuthStore.getState().token` 直接读取
2. 兜底: `localStorage.getItem('token')`
3. 兜底: 从 `localStorage.getItem('auth-storage')` 解析

## 八、耦合分析

### 注册与绑定的耦合

**1. 注册时直接创建学生（家长注册场景）**

- 家长注册成功后，**自动执行**孩子绑定流程
- 绑定在注册成功的同一个 try-catch 块中
- 绑定失败不影响注册登录成功，但会提示用户

**代码位置:** `LoginPage.tsx` 第 234-248 行

```typescript
if (isParentInvite) {
  try {
    await parentService.bindChild({
      childName,
      phone: childPhone,
      code: childCode,
      school: childSchool
    });
    toast.success('自动绑定孩子成功');
  } catch (error) {
    console.error('自动绑定失败:', error);
    toast.error('自动绑定孩子失败，请稍后重试');
  }
}
```

**2. 注册时强制绑定关系**

- 家长注册**必须**提供孩子信息才能完成注册
- 前端表单验证强制要求填写孩子姓名、手机号、验证码
- 后端 `/parent/bind` 接口会验证孩子验证码

**3. 验证码接口复用**

- 发送验证码接口 `/auth/send-code` 被多个场景复用
- 通过 `type` 参数区分用途:
  - `login` - 登录验证码
  - `register` - 注册验证码
  - `bind_child` - 绑定孩子验证码
  - `reset_password` - 重置密码验证码

**4. 登录与注册的耦合**

- 登录和注册在**同一页面组件**实现
- 通过 `isLogin` 状态切换 UI 和逻辑
- 共享手机号输入框和验证码输入框
- 注册模式下，验证码和密码字段同时显示

**5. Mock 与真实环境的耦合**

- `api.ts` 中通过 `USE_MOCK` 环境变量控制是否启用 Mock 拦截器
- Mock 数据存储在 `localStorage` 中（如 `parent_children`）
- 真实环境直接调用后端 API

## 九、表单验证逻辑

### 前端验证规则

**通用验证:**

```typescript
// 手机号
if (!phone || phone.length !== 11) {
  toast.error('请输入正确的手机号');
  return;
}

// 验证码（注册必填）
if (!isLogin && !code) {
  toast.error('请输入验证码');
  return;
}

// 密码（注册必填，至少8位）
if (!isLogin && (!password || password.length < 8)) {
  toast.error('请设置至少 8 位登录密码');
  return;
}

// 邀请码（注册必填）
if (!isLogin && !inviteCode) {
  toast.error('请输入邀请码');
  return;
}

// 邀请码有效性
if (!isLogin && !validInviteCodes.includes(inviteCode)) {
  toast.error('邀请码无效');
  return;
}

// 真实姓名（注册必填）
if (!isLogin && !name.trim()) {
  toast.error('请输入真实姓名');
  return;
}
```

**学生专属验证:**

```typescript
if (isStudentInvite) {
  if (!grade) {
    toast.error('请选择年级');
    return;
  }
  if (!age) {
    toast.error('请输入年龄');
    return;
  }
  const ageNum = parseInt(age);
  if (ageNum < 10 || ageNum > 18) {
    toast.error('请输入有效年龄（10-18岁）');
    return;
  }
  if (!school) {
    toast.error('请输入学校名称');
    return;
  }
}
```

**家长专属验证:**

```typescript
if (isParentInvite) {
  if (!childName) {
    toast.error('请输入孩子姓名');
    return;
  }
  if (!childPhone || childPhone.length !== 11) {
    toast.error('请输入正确的孩子手机号');
    return;
  }
  if (!childCode) {
    toast.error('请输入孩子验证码');
    return;
  }
}
```

## 十二、已知问题与优化建议

### 问题

1. **注册与登录耦合过紧**
   - 同一页面混合两种业务逻辑
   - 条件渲染复杂，代码可读性差
   - 建议: 拆分为独立的 RegisterPage 和 LoginPage

2. **角色判断依赖硬编码邀请码**
   - 邀请码列表硬编码在前端
   - 建议: 后端返回邀请码对应的角色，或使用白名单系统

3. **家长注册强制绑定孩子**
   - 注册流程与绑定流程强耦合
   - 建议: 允许先注册，后续再绑定孩子

4. **验证码类型硬编码**
   - `type` 字段值分散在代码中
   - 建议: 定义常量枚举

5. **表单验证逻辑分散**
   - 验证规则写在 handleSubmit 中
   - 建议: 使用 react-hook-form + zod 统一管理

6. **Token 存储冗余**
   - 同时存储在 Zustand、localStorage.token、auth-storage
   - 建议: 统一使用 Zustand persist，移除手动 localStorage 操作

### 优化方向

1. **组件拆分**
   - 提取 `PhoneInput`、`CodeInput`、`PasswordInput` 等复用组件
   - 提取 `RoleBasedFields` 组件处理角色专属字段

2. **状态管理简化**
   - 使用 URL 参数或独立页面区分注册/登录
   - 减少组件内部状态，使用 Form Data 对象聚合

3. **API 层优化**
   - 定义完整的 API 响应类型
   - 添加请求重试机制
   - 统一错误码处理

4. **用户体验**
   - 添加表单字段记忆（刷新后不丢失）
   - 优化验证码倒时器的状态同步
   - 添加网络状态检测
