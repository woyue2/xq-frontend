# 一步一步部署（本地 + 云兼容版）

## 第 1 步：准备部署文件
把以下文件放到你的部署目录（例如 `/opt/zsxq-4/deploy`）：
- `docker-compose.yml`（取自 `04-docker-compose.yml`）
- `Caddyfile`（取自 `05-Caddyfile`）
- `.env.deploy`（由 `06-.env.example` 复制）

## 第 2 步：先选择环境

### 方案对比
1. 本地验证（推荐先做）
- 适合快速联调，问题定位快
- `SITE_ADDRESS` 建议用 `localhost`
- `FRONTEND_DIST_PATH` 用本机 `dist` 绝对路径

2. 云服务器部署
- 接近生产真实形态
- `SITE_ADDRESS` 用正式域名（如 `example.com`）
- `FRONTEND_DIST_PATH` 用服务器路径（如 `/opt/zsxq-4/dist`）

推荐顺序：先本地验证，再云端上线。

## 第 3 步：构建前端与后端
在项目根目录执行：

```bash
cd /mnt/c/Users/Administrator/Downloads/zsxq-4
npm run build
docker buildx build --load -t kpqa-backend:local ./backend
```

## 第 4 步：启动容器
在部署目录执行：

```bash
docker compose --env-file ./.env.deploy up -d --force-recreate
```

## 第 5 步：数据库迁移
```bash
docker compose --env-file ./.env.deploy exec backend npx prisma migrate deploy
```

## 第 6 步：验收
```bash
docker compose --env-file ./.env.deploy ps
docker compose --env-file ./.env.deploy logs --tail 120 backend
curl -I http://127.0.0.1:3000/health
```

如果 Caddy 和域名生效，再测：
```bash
curl -I https://example.com/health
curl -I https://example.com/
```

## 第 7 步：常见差异点（本地 vs 云）
1. 前端页面空白
- 原因：`FRONTEND_DIST_PATH` 路径不对，Caddy 没挂到正确 dist
- 排查：进入 caddy 容器检查 `/srv/index.html` 是否存在

2. 域名访问失败
- 原因：DNS 未指向服务器，或 80/443 未放行
- 排查：先本机 `curl -I http://127.0.0.1`，再测域名

3. 后端镜像拉取失败
- 原因：`BACKEND_IMAGE` 与 `BACKEND_PULL_POLICY` 配置不匹配
- 排查：本地建议 `kpqa-backend:local + never`，云端仓库镜像建议 `always`

## 文件作用（简版）
1. `docker-compose.yml`
- 编排 Postgres、Redis、Backend、Caddy
2. `Caddyfile`
- ` /api ` 反代后端，其余路径服务前端静态资源
3. `.env.deploy`
- 统一切换本地/云端参数
