# Race Condition Audit Spec

## 问题描述
应用中存在竞态问题：创建问题后立即跳转到详情页，但数据库写入还未完成，导致"问题不存在"。需要系统地审计整个应用，找出所有类似的竞态问题。

## 竞态问题的特征
1. **创建后立即导航** - 创建资源后立即跳转到该资源的详情页
2. **修改后立即操作** - 修改数据后立即依赖新数据进行操作
3. **删除后立即刷新** - 删除后立即刷新列表
4. **登录后立即访问受保护资源** - 登录成功后立即访问需要权限的页面

## 已知竞态问题
- ✅ CreateQuestionPage: 创建问题后立即 navigate 到详情页

## 需要审计的区域
1. **创建操作** - 所有 create 操作后的导航
2. **修改操作** - 所有 update 操作后的状态更新
3. **删除操作** - 所有 delete 操作后的列表刷新
4. **认证流程** - 登录/注册后的权限检查
5. **审核操作** - 审核通过/拒绝后的列表更新

## 修复策略
1. **等待 API 响应** - 确保 API 返回成功后再导航
2. **乐观更新** - 本地先更新 UI，API 失败时回滚
3. **轮询重试** - 导航后如果资源不存在，自动重试
4. **延迟导航** - 添加小延迟确保数据库写入完成
