# 角色维度的端到端测试链路设计（草案）

> 目录：`tests/e2e/test-role.md`  
> 目的：从“用户视角 + 角色权限”的角度，梳理前后端联动的关键链路，方便后续用 Playwright / Jest 等实现或补全测试。

## 一、链路一：登录 → 提问 → 审核 → 通知

### 1. 学生角色（student）

- 正向主路径  
  - 场景 S1-01：学生使用白名单手机号正常登录，进入首页。  
  - 场景 S1-02：从首页跳转到“提问页”，填入合法标题与内容后提交问题。  
  - 场景 S1-03：后台（教师/审核员）通过审核该问题，学生在“通知中心”收到“审核通过”的通知。  

- 负面 / 边界场景  
  - S1-N1：手机号格式错误时，前端表单拦截发送验证码（已由 `login-page.spec.ts` 覆盖）。  
  - S1-N2：课时过期学生尝试提问 → 后端返回 `403/MEMBER_EXPIRED`，前端给出明确提示。  
  - S1-N3：学生在问题审核未通过（封禁）后，进入“我的问题列表”看到明确状态与原因。  
  - S1-N4：学生尝试调用仅教师可用的审核接口（如人工审核 API）→ 返回 `403/PERMISSION_DENIED`。  
  - S1-N5：审核回调发生异常（AI 审核失败、网络错误）时，问题保持在 `pending` 状态，学生不会看到“审核通过”的错误通知。  

### 2. 教师角色（teacher）

- 正向主路径  
  - T1-01：教师登录后台，查看“待审核队列”中的学生提问。  
  - T1-02：教师对问题执行“通过”操作，触发审核日志写入与通知创建。  
  - T1-03：教师可在后台查看审核历史（AuditLog 列表）。  

- 负面 / 边界场景  
  - T1-N1：教师尝试审核不存在的问题 → 返回 `404/QUESTION_NOT_FOUND`。  
  - T1-N2：教师对已被封禁的问题再次执行审核操作 → 返回业务错误或前端隐藏二次操作入口。  
  - T1-N3：教师访问审核接口时缺少有效 Token → 返回 `401/UNAUTHORIZED`。  

### 3. 家长角色（parent）

- 主要限制：  
  - P1-01：家长账号无法发起提问，调用提问接口应返回 `403/PERMISSION_DENIED`，前端保持展示阅读/浏览能力。  
  - P1-02：家长仅能查看公开问题及部分页签，不会看到“我的问题”“审核队列”等入口。  

## 二、链路二：提问 → 我的问题列表 → 点赞 / 收藏 → 问题详情

> 该链路主要由“学生”发起，教师/家长作为旁观或辅助角色。

### 1. 学生角色（student）

- 正向主路径  
  - S2-01：学生登录后，从首页或导航进入“提问页”，成功提交一个新问题。  
  - S2-02：在“我的问题列表”中能看到刚提交的问题，状态初始为 `pending`。  
  - S2-03：问题通过审核后，学生在“首页列表”与“我的问题列表”中都能看到状态为 `approved`。  
  - S2-04：学生在问题列表中对某个问题执行“点赞”，按钮状态变为已点赞，计数 +1。  
  - S2-05：再次点击同一问题的“点赞”，取消点赞，计数 -1。  
  - S2-06：学生对问题执行“收藏/取消收藏”，并在“我的收藏”列表中看到对应变化。  
  - S2-07：学生从列表点击问题卡片，进入“问题详情页”，看到完整内容、当前点赞/收藏状态，以及回答/评论列表。  

- 负面 / 边界场景  
  - S2-N1：学生尝试点赞不存在的问题 → 后端返回 `404/QUESTION_NOT_FOUND`，前端弹出错误提示。  
  - S2-N2：学生在未登录状态下点击“点赞/收藏” → 被重定向到登录页或看到登录提示。  
  - S2-N3：学生尝试收藏已被封禁或删除的问题 → 返回 `404` 或业务错误码，前端刷新列表状态。  
  - S2-N4：学生在“我的问题列表”中分页到边界（如超出最大页数）→ 后端返回空列表，前端渲染空态而不是报错。  

### 2. 教师角色（teacher）

- T2-01：教师在问题列表中查看所有学生问题，但默认不展示“我的问题列表”入口。  
- T2-02：教师可以点赞/收藏学生问题，用于标记优质内容（遵循与学生相同的点赞/收藏逻辑）。  
- T2-03：教师从问题详情页进入“回答”入口，提交回答后，学生在问题详情中可见。  

### 3. 家长角色（parent）

- P2-01：家长可以浏览问题列表与详情，但没有“提问”入口，也不能回答问题。  
- P2-02：家长是否允许点赞/收藏可根据产品决策决定：  
  - 若允许：行为与学生类似，但不会影响学习数据统计。  
  - 若不允许：点击相关按钮返回 `403/PERMISSION_DENIED`，前端提示“家长账号仅支持查看”。  

## 三、后续落地建议

- 后端集成测试（Jest）：  
  - 在 `backend/src/tests/integration` 下新增链路型用例，比如 `flow-login-question-audit-notification.api.spec.ts`，串联调用 `/api/auth/*`、`/api/questions`、`/api/admin/audit/*`、`/api/notifications` 等接口，覆盖上述负面/边界路径。  
- 前端 e2e 测试（Playwright）：  
  - 以本文件为“用例清单”，在 `tests/e2e` 中按角色拆分 spec 文件，如 `student-flow.spec.ts`、`teacher-flow.spec.ts`、`parent-flow.spec.ts`，逐步实现上述场景。
