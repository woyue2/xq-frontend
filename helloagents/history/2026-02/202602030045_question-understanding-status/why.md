# 学生“弄懂了”个人理解标记功能 - 变更动机

## 背景与问题

- 目前学生在老师回答问题后，缺少一种“我已经弄懂 / 还没弄懂”的轻量自我标记方式。
- 老师端已经具备提问、回答、点赞、收藏等交互，但学生自己的理解状态只能靠记忆或线下记录，难以在系统内进行追踪。
- 项目后期有可能需要基于“理解情况”做学习效果分析或推荐，但当前数据模型中完全缺失相关信息。

## 目标与价值

- 为“提问的学生”提供一个**个人专属**的理解状态标记入口，不改变现有教学流程。
- 在问答主页的题目卡片中，于“日期”旁以小字展示当前状态：
  - 红字：表示“没弄懂”；
  - 绿字：表示“弄懂了”。
- 将“学生-题目-理解状态”结构化存入数据库，为后续学习效果分析、题目质量评估等扩展预留数据基础。

## 约束与范围

- 标记主体：仅限“该题目的提问学生”可以写入/修改理解状态；其他用户最多只读或完全不可见。
- 标记对象：整道题目，而非具体某一条回答；默认前提是已有老师回答。
- 使用场景：当前仅用于学生个人自用，老师端和管理后台不新增统计入口（但数据模型允许未来扩展）。
- 技术栈约束：后端基于 Node.js + Express + Prisma + PostgreSQL，需在现有 `Question` 模型和 API 体系内演进。

## 成功判据

- 提问学生在老师回答后，可以在问答主页上看到并操作“弄懂了/没弄懂”的状态，交互流畅无明显延迟。
- 刷新页面或重新登录后，状态保持一致，说明理解状态已持久化存储。
- 非提问学生、家长、教师访问同一列表时，不会出现误导性的“理解状态”标记（可隐藏或只展示与自身相关的状态）。
- 数据库中能够查询到每道题的理解标记（按题目+用户维度），并在 `questions` 表中维护聚合统计字段，为后续数据分析提供基础。
