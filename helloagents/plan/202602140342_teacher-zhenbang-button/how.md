# 实施方案

## 1. 角色判定与按钮渲染

在 `src/pages/QuestionDetailPage.tsx` 评论渲染处保持单点判定：

- 条件：`comment.authorRole === 'teacher' && comment.content.trim() === '真棒'`
- 满足条件：渲染按钮
- 不满足条件：渲染普通文本

说明：该条件已具备，本轮只做稳定性确认，不扩散到其他模块。

## 2. 按钮点击后飘字上浮动画

同文件内增加最小局部状态与动画容器：

- 点击按钮时，向本地动画队列添加一个“真棒”实例（带唯一 id）。
- 每个实例在固定时长后自动移除。
- 队列设置最大并发实例数，避免快速连点导致叠层失控。

动画形式：

- “真棒”文字从按钮附近向上位移并淡出（上浮）。
- 使用当前项目已有 `framer-motion` 能力，不新增依赖。

## 3. 移动端适配

- 飘字容器使用相对定位到评论项内容区，保证小屏也在可视范围。
- 文案字号与位移距离采用保守值，优先保证可见和不遮挡输入框。

## 4. 验证

- 手工验证老师/学生/家长三角色的“真棒”展示差异。
- 验证快速连续点击时，动画实例数量被上限约束。
- 跑与评论服务相关的现有测试，确保后端契约未回归。
