# 变更提案：老师回答完成后，学生收到“有新回答”通知（回答创建即发送通知）

> 状态：仅规划，尚未执行（未来迭代用）

## 一、背景与问题

- 当前系统已经支持：
  - 问题审核通过/未通过时向提问学生发送 `audit_result` 通知；
  - 前端具备基础通知中心页面（列表展示 + 点击跳转到问题详情）。
- 缺失能力：
  - 当老师对某个问题提交回答后，提问学生无法第一时间获知“有新回答”；
  - 学生需要自行刷新“问题详情 / 我的问题 / 通知中心”等页面才能发现新回答，体验不连贯。

## 二、目标与价值

- 在老师成功创建回答后，立即为**问题作者（学生）**创建一条“有新回答”的通知；
- 通知中心可展示该通知，并支持点击后跳转到对应问题详情/回答位置；
- 与现有“审核结果通知”保持风格一致，便于学生集中查看学习相关事件。

## 三、范围界定

### 后端范围

- 在 `AnswerService.create` 成功写入回答后：
  - 通过 `Notification` 表新增一条记录：
    - `userId` = 问题作者 `question.authorId`；
    - `type` = `new_answer`（新增类型）；
    - `title` 示例：`老师已回答你的问题`；
    - `content`：可使用问题标题或回答内容摘要（前 N 字）；
    - `targetType`：`question` 或 `answer`（需在技术方案中明确决策）；
    - `targetId`：问题 ID 或回答 ID；
  - 确保该逻辑对回答审核流程无强耦合（即回答创建即发送通知）。
- 不改动现有 `audit_result` 通知逻辑，避免破坏已通过的测试链路。

### 前端范围

- 通知中心 `NotificationsPage`：
  - 对 `type = 'new_answer'` 的通知采用专门的图标/文案（与 `audit_result` 区分开）；
  - 点击时按 `targetType/targetId` 规则跳转到对应页面；
  - 保持与现有“问题审核通知”一致的 UI/动效。
- 可选增强（可后续单独拆分任务）：
  - 在问题详情页，根据通知信息滚动到最新回答区域或高亮提示。

### 测试与验证范围

- 后端 Jest 集成测试：
  - 覆盖“老师创建回答 → Notification 表新增 `new_answer` 记录”的链路。
- 前端 Playwright E2E：
  - 建立“学生提问 → 老师回答 → 学生在通知中心看到‘有新回答’并点击进入问题详情”的完整场景。

## 四、非目标（本次不做）

- 不引入推送（Web Push / App Push）等实时通知能力，仅限站内通知中心；
- 不改动现存审核流程（例如回答是否需要审核、审核通过是否再发一条通知）；
- 不在本轮直接实现“滚动到具体回答卡片、高亮回答”的精细交互，仅在 how.md 中预留设计思路。
