## 一、用户认证模块 (Authentication)

### 1.1 登录流程
#### 测试用例 AUTH-001: 正常登录
- **前置条件**: 无
- **输入数据**: 手机号 `13800000000`, 验证码 `1234`
- **操作步骤**:
  1. 进入 `/login` 页面
  2. 输入手机号和验证码
  3. 点击“登录”按钮
- **预期结果**:
  - 跳转至首页 `/`
  - `localStorage` 中存在 `auth-storage`
  - Toast 提示“登录成功”
- **断言方式**:
  ```typescript
  expect(window.location.pathname).toBe('/');
  expect(screen.getByText('登录成功')).toBeInTheDocument();
  ```

#### 测试用例 AUTH-002: 验证码错误
- **输入数据**: 手机号 `13800000000`, 验证码 `0000`
- **预期结果**: 停留在登录页，提示“验证码错误”

### 1.2 权限控制
#### 测试用例 AUTH-003: 路由守卫
- **操作步骤**: 未登录状态下访问 `/profile`
- **预期结果**: 自动重定向至 `/login`

### 1.3 注册流程
#### 测试用例 AUTH-004: 学生注册包含学校
- **输入数据**: 手机号 `13800138000`, 验证码 `123456`, 邀请码 `STUDENT2024`, 年级 `初一`, 年龄 `15`, 学校 `测试中学`
- **操作步骤**:
  1. 进入 `/login` 页面并切换至注册
  2. 填写手机号、验证码、邀请码
  3. 选择年级、填写年龄与学校
  4. 点击“注册”按钮
- **预期结果**:
  - 注册成功并登录
  - 学生信息包含学校字段

#### 测试用例 AUTH-005: 家长注册绑定孩子含学校

## 三、埋点与监控模块 (Tracking) ⭐新增

### 3.1 埋点上报逻辑
#### 测试用例 TRACK-001: 点击事件上报
- **前置条件**: 开启 `ENABLE_GOOD_QUESTION_INTERACTION`
- **操作步骤**: 点击首页“好问题”徽章
- **预期结果**:
  - 发送 POST 请求至 `/api/behavior/log`
  - Payload 包含 `type: 'click_good_question'`
  - Payload 包含 `timestamp` 和 `metadata`
- **断言方式**:
  ```typescript
  expect(api.post).toHaveBeenCalledWith('/behavior/log', expect.objectContaining({
      type: 'click_good_question'
  }));
  ```

#### 测试用例 TRACK-002: 上报失败重试
- **前置条件**: Mock API 返回 500 错误
- **操作步骤**: 触发埋点事件
- **预期结果**:
  - 触发重试机制（如配置了重试）
  - 最终失败时静默处理，不阻断用户交互
  - 控制台输出错误日志

#### 测试用例 TRACK-003: 页面停留时间 (Page View)
- **操作步骤**: 进入详情页 -> 停留 5秒 -> 离开
- **预期结果**:
  - `mount` 时发送 `page_view`
  - `unmount` 时发送 `page_leave`，包含 `duration: 5000`
